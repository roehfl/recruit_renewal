Current Problems

URL Authorization

SecurityConfig currently permits all requests, so /admin/** and /applications/** need explicit production rules.

Current User

Applicant identity has CurrentApplicantService, but employee/admin identity does not yet have an equivalent resolver.

StageResult Actor

StageResult update and correction currently use SYSTEM instead of authenticated admin identity.

Admin API Protection

PathAuthenticationAuthorizationPolicy
/admin/** Required Employee/admin authority Applicants receive 403; unauthenticated users receive 401.
/auth/** Endpoint-specific Endpoint-specific Login remains public; /auth/me should be authenticated.
/swagger-ui/**, /api-docs/**, /h2-console/** Environment-specific Development only Do not expose these in production without a profile policy.

Applicant API Protection

PathAuthenticationAuthorizationPolicy
/applications/** Required ROLE_APPLICANT Employee/admin users should receive 403.
Applicant-owned resources Required Role + ownership Service-level ownership checks remain mandatory.
Other applicant's application Required Hidden resource Keep the existing 404 policy.

Identity Propagation

Recommended Resolver

  • Keep CurrentApplicantService.
  • Add CurrentEmployeeService in Phase 03e-2.
  • Add CurrentAdminService only if admin authority checks need a separate abstraction.
  • Use CustomUserDetails.getUsername() as the initial actor string.

StageResult Target

  • Controller extracts principal.
  • Resolver turns principal into actor.
  • Service receives actor as a parameter.
  • Service stores actor in decidedBy or correctedBy.

Validation Rules

  • /admin/** must reject applicants.
  • /applications/** must reject employees/admins unless explicitly excepted.
  • Applicant ownership checks stay in services.
  • StageResult actor fields must not use a hardcoded constant after Phase 03e-2.
  • Applicant responses must never expose decidedBy or correctedBy.
  • Security exceptions should be handled separately from business exceptions.
