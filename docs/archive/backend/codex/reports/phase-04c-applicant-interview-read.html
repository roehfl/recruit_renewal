Executive Summary

Phase 04c adds applicant-owned, read-only interview schedule APIs.

The APIs expose only assigned candidate participant schedules for the current applicant, and only when the schedule is CONFIRMED or CANCELLED.

DRAFT schedules, other applicants, interviewer identities, admin memo, and StageResult internals are hidden.

Architecture and Domain

Entity Structure

  • Interview belongs to JobPosting and Stage.
  • InterviewParticipant belongs to Interview.
  • Applicant reads only candidate participant rows.
  • Candidate rows point to JobApplication.
  • JobApplication.applicant.id must match the current applicant.

Data Ownership

  • Applicant id is resolved from session principal.
  • No API accepts applicant id or user id.
  • Repository queries apply ownership and visibility together.
  • Non-owned or non-visible details return not found.

API List

MethodPathPurposeRequestResponse
GET /applicant/interviews?status=&from=&to= All visible schedules assigned to the current applicant. Optional query params only. ApiResponse<List<ApplicantInterviewSummaryResponse>>
GET /applicant/applications/{applicationId}/interviews?status=&from=&to= Visible schedules for one owned application. Owned application id plus optional query params. ApiResponse<List<ApplicantInterviewSummaryResponse>>
GET /applicant/interviews/{interviewId} One visible schedule detail. Interview id. ApiResponse<ApplicantInterviewDetailResponse>

Validation Rules

Visibility

  • Visible: CONFIRMED, CANCELLED.
  • Hidden: DRAFT.
  • Candidate rows only.
  • participantStatus = ASSIGNED only.
  • Withdrawn applications are inaccessible.

Query Policy

  • status=DRAFT returns 400.
  • Invalid enum values return 400.
  • from >= to returns 400.
  • Time range uses overlap semantics.

Forbidden Response Fields

  • Admin memo and cancel/internal memo.
  • Other candidates or applicant identities.
  • Interviewer employee id/name/department.
  • StageResult status, history, and announcement fields.
