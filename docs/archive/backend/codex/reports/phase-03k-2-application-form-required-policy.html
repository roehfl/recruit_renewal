Phase 03k-2 - Application Form Required Policy

Completed Generated 2026-05-22

Executive Summary

Phase 03k-2 implements the end-to-end split between section visibility and submit-required policy. ApplicationFormConfig now stores explicit requireXxx fields, admin/public detail responses expose both use and require values, and public list policy still hides the raw config.

Submit validation and dashboard readiness now use the same rule: a form section blocks submit only when useXxx and requireXxx are both true. Attachment required enforcement remains deferred.

Architecture & Domain

JobPosting owns one ApplicationFormConfig. The existing useXxx fields continue to represent visibility and applicant section access. New requireXxx fields represent final-submit blocking and dashboard required-readiness only.

Public list responses still do not expose applicationFormConfig. Instead, the list projection includes nullable use/require fields and returns the normalized applicationFormRequiredPolicy.

Manual MariaDB DDL

No migration framework is active. Use the manual DDL and backfill below before deploying to a persistent MariaDB database. Deploying the Java change without these columns will break runtime reads/writes, and existing rows need education, career, and military backfill to preserve previous submit-required behavior.

ALTER TABLE application_form_config
    ADD COLUMN require_education BOOLEAN NOT NULL DEFAULT FALSE,
    ADD COLUMN require_career BOOLEAN NOT NULL DEFAULT FALSE,
    ADD COLUMN require_certificate BOOLEAN NOT NULL DEFAULT FALSE,
    ADD COLUMN require_language BOOLEAN NOT NULL DEFAULT FALSE,
    ADD COLUMN require_military BOOLEAN NOT NULL DEFAULT FALSE,
    ADD COLUMN require_award BOOLEAN NOT NULL DEFAULT FALSE,
    ADD COLUMN require_gap_period BOOLEAN NOT NULL DEFAULT FALSE;

UPDATE application_form_config
SET require_education = use_education,
    require_career = use_career,
    require_military = use_military;
