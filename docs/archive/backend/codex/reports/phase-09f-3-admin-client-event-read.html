1. 요약

Phase 09f(지원자 화면 진단 로그)의 세 번째 슬라이스. 관리자 조회 파이프라인을 구현했다 — GET /api/admin/client-events(검색 11파라미터) + GET /api/admin/client-events/{id}(단건 조회). 권한별 민감 필드 projection(마스킹/원문)과 조회 가드(page size / 날짜 범위 / default 범위)를 포함한다.

이 슬라이스로 09f 수집 → 조회 파이프라인이 완성됨. retention cleanup(bulk delete + 스케줄러)은 09f-4로 이월. 프론트엔드 연동은 별도 FE 프로젝트(09f-2).
민감 필드 원문은 ROLE_PRIVACY_ADMIN 보유 시에만 반환. ROLE_RECRUIT_ADMIN은 4개 필드(ipAddress/userAgent/principalHash/stackSummary)가 ***으로 마스킹됨. ROLE_ADMIN 단독 사용자는 의도적으로 403(감사 read 선례와 동일한 privacy-tightening).

6. 도메인 / 클래스 구조

ClientEventLogNotFoundException

exception · 신규 · HTTP 404

단건 조회(getEvent) 시 id 부재. RuntimeException 단순 상속. GlobalExceptionHandler에서 404 매핑.

InvalidClientEventQueryException

exception · 신규 · HTTP 400

조회 파라미터 검증 실패. page 음수 / size 범위 초과 / 날짜 범위 역전 / 90일 초과. RuntimeException 단순 상속.

ClientEventLogRepository (수정)

domain.repository · Repository 마커 · 09f-1 기존 + search 추가

search(@Query) 추가. 9 필터 파라미터 + Pageable. null 필터는 IS NULL OR 패턴으로 생략. ORDER BY c.receivedAt DESC, c.id DESC 고정.

ClientEventLogResponse

dto.response · Response DTO · Java record · 신규

34필드 record. from(log, includeSensitive) 정적 팩토리. includeSensitive=false 시 4필드 → ***. 단일 private static String mask(String, boolean) 헬퍼.

ClientEventLogReadService

service · @Service · @Transactional(readOnly=true) · 신규

가드(validatePaging/validateRange) + normalize + repository 호출 + projection 위임. MAX_PAGE_SIZE=100, MAX_RANGE_DAYS=90, DEFAULT_RANGE_DAYS=7. Duration 비교로 90일 체크(toDays() 소수 버림 없음).

AdminClientEventLogController

controller · @RestController · 신규

GET /admin/client-events + GET /admin/client-events/{id}. includeSensitive(userDetails) — authorities에 ROLE_PRIVACY_ADMIN 포함 시 true. AdminAuditController 선례 패턴.

SecurityConfig (수정)

config · 수정 · narrow matcher 삽입

GET /api/admin/client-events/** → ROLE_RECRUIT_ADMIN/ROLE_PRIVACY_ADMIN. broad /api/admin/** 앞에 위치. ROLE_ADMIN 단독 → 403(의도적).

9. 남은 이슈

PRIVACY_ADMIN 컨트롤러 테스트 부분 커버리지
AdminClientEventLogControllerTest.PRIVACY_ADMIN은_원문을_본다는 ipAddress/stackSummary 2필드만 검증. userAgent/principalHash 원문은 서비스 레벨 테스트에서 검증됨. mask()가 단일 헬퍼라 런타임 위험 낮음. 향후 컨트롤러 테스트 보강 권장.
ROLE_ADMIN 403 전용 테스트 미포함
narrow matcher에서 ROLE_ADMIN 단독 사용자가 403을 받는지 전용 테스트 없음. SecurityConfig 주석에 의도 명시. APPLICANT_권한은_403이다로 구조 검증됨.
