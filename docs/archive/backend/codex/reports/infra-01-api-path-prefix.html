Infra 01 · 전역 /api 경로 Prefix

신영증권 채용 Renewal 백엔드 · 컨트롤러 엔드포인트 공통 prefix 적용
Status: 완료  ·  Generated: 2026-06-01  ·  Type: cross-cutting infra

Executive Summary

모든 애플리케이션 컨트롤러 엔드포인트 앞에 공통 /api prefix를 부여했다. 컨트롤러 25개를 개별 수정하지 않고 WebMvcConfigurer.addPathPrefix로 com.shinyoung.recruit.controller 패키지에 한해 중앙 적용했다. Spring Security 요청 매처와 컨트롤러 MockMvc 테스트 경로(28개 파일)를 함께 /api로 정렬했다.

H2 datasource는 변경하지 않았다. 메인 application.yaml의 jdbc:h2:~/recruit는 이미 파일(인디스크) 모드로 ~/recruit.mv.db에 영속되므로 현 설정을 유지했다(사용자 확인). 테스트용 jdbc:h2:mem:testdb는 ephemeral 목적이라 인메모리를 유지한다.

진행 가능: 라우팅·인가 변경은 검증 완료. 프론트엔드/프록시 base URL을 /api로 맞추면 된다.

Architecture

적용 방식

PathMatchConfigurer.addPathPrefix("/api", HandlerTypePredicate.forBasePackage("com.shinyoung.recruit.controller")) — 핸들러 매핑 단계에서 우리 컨트롤러 패키지에만 prefix를 부여한다. springdoc·H2 콘솔 핸들러는 다른 패키지라 영향받지 않는다.

인가 경로 정렬

Security 매처는 실제 요청 URI를 기준으로 동작하므로, 컨트롤러 대상 매처를 /api/...로 이동했다. 권한 매핑(role) 자체는 동일하다.

Validation & Policy

  • prefix는 com.shinyoung.recruit.controller 패키지 핸들러에만 적용.
  • 보안 인가 규칙은 의미 변화 없이 경로만 /api로 이동(권한 매핑 동일).
  • 비-컨트롤러 인프라 엔드포인트는 prefix 대상 아님.

사전-실패 (본 변경과 무관)

일부 컨트롤러 테스트 fixture가 공고 접수기간(예: 2026-05-01~2026-05-30)을 사용하는데, 실행 시점 시스템 날짜가 2026-06-01이라 JobApplicationService.create의 접수기간 검증 (접수기간 내에만 지원서를 처리할 수 있습니다)에서 fixture 셋업이 실패한다. 이는 HTTP 라우팅 이전 서비스 계층 예외로 /api prefix와 무관하며, 404/405/401 라우팅 실패가 아니다.

Remaining Issues

  • 날짜 의존 fixture를 고정 Clock 주입/동적 접수기간으로 안정화(테스트 하드닝).
  • 컨트롤러 소스에 prefix가 보이지 않으므로, 신규 컨트롤러는 도메인 상대경로만 작성한다는 규칙 공유 필요.

Next Phase Recommendation

  • 테스트 클럭/접수기간 fixture 안정화.
  • 프론트엔드/배포 프록시 base URL /api 정렬 확인.
