5. 도메인 / 클래스 구조

ClientEventLogRepository (수정)

domain.repository · Repository 마커 · 09f-1 기존 + deleteByReceivedAtBefore 추가

@Modifying(flushAutomatically = true) @Query("DELETE FROM ClientEventLog c WHERE c.receivedAt < :threshold") 단일 JPQL DELETE. 엔티티 로딩 없음. flushAutomatically는 프로젝트 @Modifying 관례 정렬.

ClientEventLogCleanupService

service · @Service · @Transactional · 신규

threshold = LocalDateTime.now(clock).minusDays(retentionDays). retentionDays 기본 90(client-event-log.retention-days). strict < — receivedAt == threshold 로그 유지. 스케줄러와 수동 트리거 양쪽에서 호출됨.

SchedulingConfig

config · @Configuration · @EnableScheduling · 신규 · 프로젝트 최초

@EnableScheduling 프로젝트 최초 도입. 현재 사용처는 ClientEventLogCleanupScheduler 하나. @SpringBootTest 컨텍스트에도 스케줄러가 활성화됨(cron 04:00 — 테스트 시간대 간섭 위험 낮음).

ClientEventLogCleanupScheduler

service · @Component · @Scheduled · 신규

@Scheduled(cron = "${client-event-log.cleanup-cron:0 0 4 * * *}"). 예외 무전파 — try-catch로 모든 예외를 log.error만. 스케줄링 스레드/다음 실행 보호.

ClientEventLogCleanupResponse

dto.response · Response DTO · Java record · 신규

record(int deletedCount). cleanup 결과 단순 응답. ApiResponse<ClientEventLogCleanupResponse>로 래핑됨.

AdminClientEventLogController (수정)

controller · @RestController · 09f-3 기존 + cleanup POST 추가

POST /admin/client-events/cleanup 추가. ClientEventLogCleanupService.cleanup() 위임. 컨트롤러 내 인증 로직 없음 — SecurityConfig narrow matcher가 ROLE_PRIVACY_ADMIN 전용으로 게이팅(retention write 관례와 동일).

SecurityConfig (수정)

config · 수정 · narrow matcher 삽입

POST /api/admin/client-events/cleanup → hasAuthority("ROLE_PRIVACY_ADMIN")를 기존 GET /api/admin/client-events/** matcher 앞, broad /api/admin/** matcher 앞에 삽입. matcher 평가 순서가 보안 요구사항. ROLE_RECRUIT_ADMIN은 cleanup POST에서 403.

8. 남은 이슈

수동 cleanup 트리거의 행위자 감사 추적 없음
POST /api/admin/client-events/cleanup은 삭제 건수만 반환하며 ActivityLog에 행위자를 기록하지 않는다. 진단 로그 정리는 운영 진단 목적이라 설계상 ActivityLog 계측 제외. 규정 요건 발생 시 후속 phase 추가 가능.
경계값(정확히 90일) 테스트의 결정성
receivedAt == threshold(정확히 90일 경과 시점) 시나리오는 시스템 Clock의 ms 오차로 비결정적. 91일/89일 쌍으로 경계를 검증하는 방식 사용.
PRIVACY_ADMIN 조회 원문 테스트 부분 커버리지
AdminClientEventLogControllerTest.PRIVACY_ADMIN은_원문을_본다는 ipAddress/stackSummary 2필드만 검증. userAgent/principalHash 원문은 ClientEventLogReadServiceTest에서 커버됨(09f-3 Known Limitations 동일).
@EnableScheduling과 통합 테스트 컨텍스트
SchedulingConfig가 주 컨텍스트에 포함되므로 @SpringBootTest 통합 테스트에서도 스케줄러가 활성화된다. cron이 0 0 4 * * *(매일 04:00)이므로 현재 테스트 실행 시간대 간섭 위험은 낮다. 추후 단기 주기 스케줄러가 추가될 경우 해당 테스트에서 @MockBean이나 프로파일 분리로 격리할 것.
