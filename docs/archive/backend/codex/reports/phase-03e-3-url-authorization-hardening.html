Recruit Backend - Phase 03e-3

URL Authorization Hardening Completed Generated: 2026-05-19

Executive Summary

Phase 03e-3 applies URL-level authorization to the main admin and applicant API families while preserving the existing session-based authentication structure.

/admin/** now requires ROLE_ADMIN or ROLE_RECRUIT_ADMIN. /applications/** now requires ROLE_APPLICANT.

The phase deliberately does not add JSON 401/403 handlers. Default Spring Security failure responses remain in place until Phase 03e-4.

Architecture and Domain

Authorization Structure

  • DeptRoleMapping.roleName uses full authority names such as ROLE_ADMIN.
  • LDAP mapping passes role names directly into SimpleGrantedAuthority.
  • SecurityConfig therefore uses hasAnyAuthority(...).
  • Applicant APIs use ROLE_APPLICANT.

Data Ownership

  • URL authorization verifies caller type and authority.
  • Service-level ownership checks remain responsible for applicant resource ownership.
  • Other applicant resource access still follows hidden-resource 404 behavior.
  • No entity relationship changed.

Business Rules

  • Applicant users are denied from admin URLs.
  • Non-admin employees are denied from admin URLs.
  • Employee/admin users are denied from applicant URLs.
  • Public posting reads remain available without login.
  • Applicant ownership is still checked in services.

Security Handler Policy

  • 401/403 body shape is not customized in this phase.
  • Tests assert HTTP class/status behavior, not JSON body.
  • ApiResponse.fail security responses are Phase 03e-4 scope.
