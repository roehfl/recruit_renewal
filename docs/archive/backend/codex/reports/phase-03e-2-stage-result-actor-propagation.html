Recruit Backend - Phase 03e-2 StageResult Actor Propagation

Completed Generated: 2026-05-19

Executive Summary

Phase 03e-2 replaces the temporary StageResult admin actor value with the authenticated employee login id.

CurrentEmployeeService validates that the principal is an employee and returns CustomUserDetails.getUsername() as the actor.

Single update, bulk update, and post-announcement correction now require an actor and store it in decidedBy or correctedBy.

The phase is complete and can move to URL authorization hardening.

Architecture and Domain

Main Classes

  • CurrentEmployeeService: validates employee principal and returns actor.
  • StageResultService: stores actor in decidedBy for single and bulk update.
  • StageResultCorrectionService: stores actor in latest decidedBy and history correctedBy.
  • StageResultController: resolves actor at the controller boundary.

Entity Structure

  • No entity relationship changed.
  • StageResult.decidedBy remains a string field.
  • StageResultCorrectionHistory.correctedBy remains a string field.
  • No Employee FK, audit actor entity, cascade, or migration was added.

Validation and Policy

Business Rules

  • Actor source is CustomUserDetails.getUsername().
  • Actor must not be null or blank.
  • Current principal must have userType == Employee.
  • Single and bulk update remain limited to IN_PROGRESS stages.
  • Correction remains limited to RESULT_ANNOUNCED and CLOSED stages.

Exposure Rules

  • StageResultCorrectionHistoryResponse.correctedBy remains admin-only.
  • AdminStageResultResponse.decidedBy was not added.
  • ApplicantStageResultResponse was not changed.
  • Applicant JSON does not expose decidedBy or correctedBy.
