Phase 06b - 관리자 초기화 + 면접관 평가 입력

구현 완료 작성일: 2026-05-29

요약

Phase 06b는 Phase 06a InterviewEvaluation 도메인 위에 첫 API 레이어를 추가합니다.

관리자는 CONFIRMED 면접에 대해 ASSIGNED 후보자 × ASSIGNED 면접관 조합의 DRAFT 평가 행을 명시적으로 초기화하고, 각 면접관은 자신의 평가만 조회/임시저장/제출합니다.

StageResult는 어디서도 참조·변경하지 않습니다. 관리자 조회 집계(06c)와 재개(06d)는 범위 밖입니다.

초기화 흐름

interview = CONFIRMED? → ASSIGNED 후보자 조회 × ASSIGNED 면접관 조회 → 조합별 존재 확인 → 없는 조합만 DRAFT 생성

멱등: 이미 존재하는 조합은 alreadyExistedCount로 집계되고 새로 만들지 않습니다. CANCELLED 참가자는 조회 단계에서 제외됩니다. CONFIRMED가 아니면 400.

평가 상태 전이 (06b 범위)

(admin initialize) → DRAFT → (save) → DRAFT → (submit) → SUBMITTED

submit은 grade + recommendation이 모두 있어야 하며 submittedAt을 설정합니다. SUBMITTED 행은 본 slice에서 더 이상 수정할 수 없습니다(reopen은 06d). submit은 최종 수정용 body를 선택적으로 받습니다.

검증 및 비즈니스 규칙

구분규칙
초기화interview는 CONFIRMED여야 함 (DRAFT/CANCELLED → 400)
초기화ASSIGNED 후보자 × ASSIGNED 면접관 조합만 생성
초기화멱등: 기존 조합 skip, alreadyExistedCount 집계
조회/저장모든 진입점이 먼저 visible(CONFIRMED/CANCELLED) ASSIGNED 면접관 participant를 찾고, 그 participant id로 평가를 조회 → cancelled/비참가자는 404
저장interview CONFIRMED + 면접관 ASSIGNED + 후보자 ASSIGNED
저장DRAFT만 수정 가능, comment 최대 2000자
제출저장 가드 + grade/recommendation 필수 → SUBMITTED, submittedAt 설정 (body 없으면 기존 저장값 사용)
조회 격리목록·상세 모두 participant id 기준, 본인 평가만 노출. cancelled 면접관은 본인 과거 평가도 상세 조회 불가
