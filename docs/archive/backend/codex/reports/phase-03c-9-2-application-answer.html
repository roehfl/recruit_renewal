Recruit Backend - Phase 03c-9-2

ApplicationAnswer + Applicant Question/Answer API

Completed Generated 2026-05-18 Self-contained HTML

Executive Summary

Phase 03c-9-2 adds applicant-side question and answer support. Applicants can read active questions for their own application and replace-save answers while the application is writable.

The implementation adds `ApplicationAnswer` with snapshot fields, read/replace service logic, HTTP APIs, tests, and documentation. Full `clean test` passed.

This phase does not modify `ApplicationSubmitValidator`; required answer validation is intentionally deferred to Phase 03c-9-3.

Scope

Implemented

  • `ApplicationAnswer` entity and repository
  • Applicant question list API
  • Applicant answer replace API
  • Question snapshot storage
  • DRAFT writable policy reuse
  • Service and controller tests

Not Implemented

  • Submit validator answer integration
  • Admin answer read API
  • `GET /applications/{applicationId}/answers`
  • PUT, HTTP DELETE, individual answer delete
  • StageResult

Deferred

  • Choice options
  • File answer type
  • Attachment linkage
  • Question revision/reopen policy
  • Answer access audit logs

Architecture And Domain

Relationship Summary

  • `ApplicationAnswer` N:1 `JobApplication`
  • `ApplicationAnswer` N:1 `JobPostingQuestion`
  • No answer collection on `JobApplication`
  • No answer collection on `JobPostingQuestion`
  • No cascade or orphanRemoval added

Snapshot Policy

  • `questionTextSnapshot`
  • `categorySnapshot`
  • `answerTypeSnapshot`
  • `requiredSnapshot`
  • `minLengthSnapshot`, `maxLengthSnapshot`
  • `sortOrderSnapshot`
ClassTypeResponsibility
`ApplicationAnswer`EntityStores one applicant answer and question snapshot.
`ApplicationAnswerRepository`RepositoryQueries, deletes, and persists answers by application/question.
`ApplicationAnswerService`ServiceOwns applicant question read and answer replace rules.
`ApplicationAnswerController`ControllerExposes applicant GET questions and POST answers APIs.
`ApplicationQuestionResponse`Response DTOReturns question policy plus current answer fields.

API List

MethodPathPurposeRequestResponse
GET /applications/{applicationId}/questions Read active posting questions with current applicant answers. None ApiResponse<List<ApplicationQuestionResponse>>
POST /applications/{applicationId}/answers Replace-save applicant answers. ApplicationAnswerReplaceRequest ApiResponse<List<ApplicationQuestionResponse>>

DTO Policy

DTOFieldsNotes

`ApplicationQuestionResponse``questionId`, `questionText`, `helperText`, `category`, `answerType`, `required`, `minLength`, `maxLength`, `sortOrder`, `answerId`, `answerText`, `updatedAt`GET and POST return the same shape.

Validation And Policy

AreaPolicy
ReadDRAFT, SUBMITTED, and WITHDRAWN are readable by the owner.
WriteOnly DRAFT application, PUBLISHED job posting, and active reception period.
Question sourceOnly active `JobPostingQuestion` rows for the application's job posting.
Replace saveDelete all existing answers for the application, then save requested rows.
Blank answerAllowed during DRAFT save, even for required questions.
LengthQuestion maxLength, SHORT_TEXT 500, LONG_TEXT 5000 are enforced.
Submit validationDeferred to Phase 03c-9-3.
Required question blanks are intentionally accepted at DRAFT save. Final submission must validate them in the next phase.
