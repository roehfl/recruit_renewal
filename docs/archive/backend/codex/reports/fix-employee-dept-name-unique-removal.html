1. 문제 / 해결

문제. Employee.deptName에 @Column(unique = true)가 걸려 있었다. 같은 부서 임직원은 여러 명일 수 있고 JIT는 LDAP deptName을 그대로 저장하므로, 같은 부서의 두 번째 임직원이 최초 로그인하면 unique 충돌로 JIT 저장이 실패 → 로그인 실패가 된다. (05y race 복구는 이 경우를 정확히 "복구 대상 아님"으로 전파 — 결함은 제약 자체)
해결. deptName을 일반 컬럼으로 완화. JIT/인증 로직과 race 복구 semantics(loginId race만 복구, 그 외 제약 위반은 전파)는 변경 없음. 동일 deptName 임직원 2명 저장을 리포지토리 테스트로 실증.

4. 운영 DDL / 남은 이슈

운영 MariaDB에 기존 unique 인덱스가 있다면 수동 제거 필요. 05y의 uk_users_login_id 추가와 같은 DDL 작업 묶음으로 처리 권장. 
-- 1) unique 제약/인덱스명 확인
SELECT CONSTRAINT_NAME
FROM INFORMATION_SCHEMA.TABLE_CONSTRAINTS
WHERE TABLE_SCHEMA = DATABASE()
  AND TABLE_NAME = 'employee'
  AND CONSTRAINT_TYPE = 'UNIQUE';
-- 또는: SHOW INDEX FROM employee;

-- 2) 확인된 이름으로 제거
ALTER TABLE employee DROP INDEX <확인된_인덱스명>;
