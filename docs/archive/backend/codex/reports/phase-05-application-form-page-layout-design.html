Phase 05 - Application Form Page Layout Design

Design Complete Generated: 2026-05-26

Executive Summary

Phase 05 designs a backend page-layout contract for applicant application forms. It keeps section data persistence and submit validation in the existing section APIs and policy services.

The design adds ApplicationFormPage and ApplicationFormPageItem as page/section placement concepts under JobPosting.

ApplicationFormConfig remains responsible for use/required policy, JobPostingQuestion remains responsible for question required policy, and JobPostingAttachmentRequirement remains responsible for attachment required policy.

Phase 05a domain implementation is now complete; this design can move forward to 05b admin layout management.

Architecture / Domain

Entity Relationship

  useXxx / requireXxx policy

  attachment enabled / required policy

JobPostingQuestion:
  question/answer enabled / required policy

Data Ownership Rules

  • Layout owns page placement only.
  • ApplicationFormConfig owns non-attachment section enable/required policy.
  • JobPostingQuestion owns question/answer enable/required policy.
  • JobPostingAttachmentRequirement owns attachment policy.
  • Existing section APIs own application data saves.
  • The backend does not store Vue component names.

BASIC_INFO save is backed by the existing root draft update endpoint POST /applications/{applicationId}. The current request updates jobPositionId; broader personal basic-info fields require a later endpoint or request expansion.

QUESTION_ANSWER uses GET /applications/{applicationId}/questions and POST /applications/{applicationId}/answers.

Validation / Policy

Business Rules

  • At least one page is required.
  • Every page must have at least one item.
  • Page numbers and page sort orders are unique per posting.
  • Item sort order is unique within a page.
  • Section type is unique across the full layout.
  • Disabled sections cannot be placed.
  • Enabled sections must be placed once.
  • Required sections must be placed.
  • QUESTION_ANSWER is placed when active questions exist.

State Rules

  • DRAFT postings can edit layout structure.
  • Reception-started postings block structure mutation.
  • Published posting layout edits need a later explicit policy.
  • Publish must validate layout consistency.
  • Existing postings may use deterministic fallback until migration is complete.
