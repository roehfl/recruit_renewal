Shinyoung Recruit Backend

Phase 03i-2 Attachment File Upload

Implemented Applicant Upload Updated: 2026-05-20

Executive Summary

Implemented applicant-owned single physical file upload on top of the existing attachment metadata slice.

The existing JSON metadata APIs remain, but metadata replace now manages only METADATA_ONLY rows and preserves STORED file-backed rows.

Storage internals and download availability remain hidden from applicant/admin metadata responses.

Scope

Completed

  • POST /applications/{applicationId}/attachments/files
  • PhysicalFileStatus enum and entity field
  • Local filesystem storage abstraction
  • Filename, extension, content type, size, count, and total-size validation
  • Rollback cleanup for just-stored files
  • Metadata replace hardening

Not Implemented

  • Applicant/admin download
  • Admin upload
  • Delete endpoint
  • Orphan cleanup scheduler
  • S3/NAS/object storage

Deferred

  • downloadAvailable field
  • Dashboard readiness
  • Submit validator changes
  • Attachment required policy
  • Virus scan/DLP integration

Remaining Issues

  • Delete, admin upload, orphan cleanup, malware scanning, and required attachment policy remain deferred.
