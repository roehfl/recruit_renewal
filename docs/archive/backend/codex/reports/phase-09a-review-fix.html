1. 요약

Phase 09a 구현 결과에 대한 코드 리뷰 지적 5건(Major 1 · Medium 2 · Low 2)을 전부 반영했다. 핵심은 request-derived 문자열의 길이 제한/sanitize — 외부에서 들어온 긴 X-Request-Id·User-Agent 가 audit insert 실패를 일으켜 비즈니스 트랜잭션 rollback(recordInCurrentTx)이나 9b egress fail-close 차단으로 번지는 경로를 막았다.

9b 착수 가능 — egress fail-close 가 전제하는 normalize·인덱스·운영 DDL·ADR 확정이 모두 완료됐다.

3. Normalize 정책 (Major-1)

CorrelationIdFilter.resolve(X-Request-Id) null/blank → UUID 생성 (기존) trim 후 100자 초과 → UUID 대체 (신규) ISO 제어문자 포함(CR/LF/TAB…) → UUID 대체 (신규 — response echo header injection·WAS reject 방어. 최초 CR/LF 만 → 2차 리뷰에서 Character::isISOControl 전체로 확대) ActivityLogService.safe(value, max) — 저장 직전 [\r\n\t] → ' ' 치환 → trim → blank 면 null → max 초과분 truncate
필드컬럼 길이 = truncate 한도
actorId100
actorRoleSnapshot255
reasonMessage1000
correlationId100 (MDC resolve 후 적용)
ipAddress64
userAgent512
truncate-not-fail: 감사 기록은 잘려도 남는 것이 우선이다. reject 했다면 외부 입력이 곧 감사 실패 → 비즈니스 rollback 유발 수단이 된다. targetId 는 내부 파생 값(entity id)이라 대상에서 제외.

4. Fallback Secret 게이트 (Low-5)

secret blank 인 경우: prod profile 활성 → 기동 실패 (flag 무관 — 이중 가드) allow-fallback ≠ true → 기동 실패 (기본값 — profile 이름 무관 fail-closed) allow-fallback = true → fallback secret + 경고 로그 (local/test 전용)
설정 키audit.allow-fallback-secret (= env AUDIT_ALLOW_FALLBACK_SECRET, 기본 false)
local 개발 영향AUDIT_HMAC_SECRET 미설정 시 이제 기동 실패 — AUDIT_ALLOW_FALLBACK_SECRET=true 명시 필요(기존 AES_SECRET_KEY 필수와 동일 방식)
테스트 영향없음 — test yaml 에 secret 이 이미 설정됨

신규 테스트 (Major-1 검증)

  • 길이 100 초과 X-Request-Id → UUID 대체 (+경계 100자는 재사용, CR/LF 는 대체)
  • 2000자 userAgent → 512자 truncate 저장
  • CR/LF/TAB 포함 reasonMessage → 공백 치환 sanitize
  • actorId/roleSnapshot/correlationId/ip/reasonMessage 동시 초과 → 전부 truncate, insert 성공
  • whitespace-only 입력 → null 저장
  • allow-fallback 기본값 기동 실패 / true 시 fallback / prod+true 도 기동 실패

7. 잔여 이슈

  • 이연 safe()(서비스 저장 경로)는 CR/LF/TAB 외 제어문자는 치환하지 않음 — 표시 계층(9b read API) 이슈로 이연. (필터의 echo 경로는 2차 보완으로 ISO control 전체 거부.)
  • 이연 truncate 는 정보 손실 — 원문 보존 필요 사례가 생기면 metadataJson allowlist 로 이동 검토(9b).
  • 9b 필수 actorType=EMPLOYEE/APPLICANT → actorId 필수 검증(2차 리뷰) — emitter 가 actorId 를 보장하는 9b 계측 시점에 추가(선반영 시 emitter 부재 상태에서 insert-실패 경로만 생김).
  • 운영 체크 배포 시 AUDIT_HMAC_SECRET 주입 + phase-09a-activity-log-ddl.sql 반영(ddl-auto validate/none 환경).
