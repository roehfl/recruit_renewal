Phase 06d - 평가 재개 + StageResult 경계

구현 완료 작성일: 2026-05-29

요약

Phase 06d는 관리자 평가 재개(reopen) 커맨드를 추가합니다. SUBMITTED 평가를 DRAFT로 되돌리고 submittedAt을 초기화하면, 해당 면접관이 06b API로 다시 수정·제출할 수 있습니다.

재개 동작은 감사 로그(actor, 평가 id, 면접 id, 이전 제출시각, 재개시각)로 기록됩니다. 등급/추천/코멘트는 보존되고 상태와 제출시각만 바뀝니다.

핵심 정책: 평가 도메인은 StageResult를 어디서도 참조/주입/변경하지 않습니다. 최종 합불은 기존 StageResult 수동 확정 워크플로우가 담당합니다.

API 목록

메서드경로권한요청응답
POST /admin/interviews/{interviewId}/evaluations/{evaluationId}/reopen ADMIN / RECRUIT_ADMIN - AdminEvaluationItemResponse

응답은 ApiResponse<T>로 감쌉니다. 재개 후 status=DRAFT, submittedAt=null.

상태 전이

SUBMITTED → (admin reopen) → DRAFT → (interviewer save/submit · 06b) → SUBMITTED

재개는 submittedAt을 초기화하고 등급/추천/코멘트는 보존합니다. DRAFT만 수정 가능하므로 재개 후 면접관이 다시 작성·제출할 수 있습니다.

StageResult 경계 정책

비변경 보장 InterviewEvaluation · InterviewEvaluationAdminService · InterviewerEvaluationService · 컨트롤러 어디에도 StageResult/StageResultRepository/StageResultService에 대한 필드·파라미터·import·호출이 없습니다. 보장은 구조적으로 성립합니다.

StageResult 반영(reflect) 커맨드(POST /admin/stages/{stageId}/results/reflect-interview-evaluations 등)는 명시적으로 보류합니다(설계 §12.3). 점수화 기준이 아직 정의되지 않았고, 기존 StageResult 수동 update/bulk-update 워크플로우로 충분합니다.
