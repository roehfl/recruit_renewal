Architecture Domain

Entity Relationship Summary

  • Interview belongs to JobPosting and Stage.
  • InterviewParticipant belongs to Interview.
  • Candidate participants point to JobApplication.
  • Interviewer participants point to Employee.
  • StageResult remains separate from scheduling state.

Data Ownership Rules

  • Applicant reads use current applicant and assigned candidate participant rows.
  • Interviewer reads use current employee and assigned interviewer participant rows.
  • Admin APIs remain behind /admin/** authority checks.
  • Request parameters never accept applicant id or employee id for personal reads.

Validation Rules

Cancellation

  • Only CONFIRMED interviews can be cancelled.
  • Cancel changes only Interview.status.
  • Participant rows remain ASSIGNED.
  • Cancelled schedules remain visible to assigned users.

Visibility

  • Applicant/interviewer reads expose CONFIRMED and CANCELLED.
  • DRAFT remains hidden outside admin APIs.
  • Non-owned detail reads are hidden as not found.
  • Cancelled participant rows are hidden.

StageResult

  • Scheduling confirm reads prior-stage pass eligibility.
  • Scheduling cancel does not mutate results.
  • Read DTOs do not expose result internals.
  • Evaluation integration is deferred to Phase 05.
