Executive Summary

Phase 03i-4-2 implemented applicant and admin attachment delete commands using a soft lifecycle state.

Deleted attachment rows are retained as PhysicalFileStatus.DELETED, hidden from normal metadata lists, and remain non-downloadable.

Previously stored physical files are deleted after the DB transaction commits; physical delete failure is logged and does not roll back the soft delete.

Transaction And Physical Delete

  • DB state changes to DELETED first.
  • For previously STORED rows, physical delete is registered with transaction afterCommit.
  • METADATA_ONLY rows do not request physical delete.
  • Missing physical files are treated idempotently.
  • Physical delete failure is logged only and does not roll back the DB soft delete.
  • Logs avoid full storage key and absolute path exposure.
