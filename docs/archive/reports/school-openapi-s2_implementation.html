요약

지원서 학력이 들고 있던 School 마스터 참조 schoolId(Long PK)를 외부 학교코드 schoolCode(String) + 출처 schoolSource(enum)로 교체했다.

학교별 퍼널 통계는 School 테이블 조회를 끊고 학교코드로 그룹핑하도록 바꿨다. 그룹 표시명은 지원서 학력 행의 schoolName을 쓴다.

기존 school_id 값은 폐기했다. 이관 없이 버리기로 확정된 사항이라 마이그레이션 코드는 만들지 않았다.

백엔드 전 구간(엔티티·DTO·통계·테스트)이 새 필드로 정렬됐다. 프론트는 아직 schoolId를 보내므로 S3에서 맞춘다.

결정 로그

#결정근거
1학교 그룹의 groupId를 null 로 둔다학교코드는 Long PK 가 아니다. CERTIFICATE dimension 이 이미 같은 방식이고, 프론트가 null 을 처리하고 있어 응답 스키마를 건드릴 필요가 없다
2그룹 표시명을 지원서 학력 행의 schoolName에서 가져온다마스터 테이블이 없어져 이름을 되찾을 곳이 지원서뿐이다. 같은 코드의 첫 행 이름을 대표로 쓴다
3schoolSource를 enum 으로 저장코드 체계가 출처마다 달라 코드 단독으로는 해석할 수 없다. 프로젝트 스타일대로 @Enumerated(STRING)
4dangling 테스트 삭제참조 대상 테이블이 없어져 성립하지 않는 시나리오다. 직접입력(코드 없음) → '기타'는 기존 테스트가 이미 덮는다
5school_id 컬럼 DROP 을 코드에 넣지 않는다ddl-auto: update는 컬럼을 삭제하지 않는다. 운영 스키마 변경은 관리형 DDL 로 처리하는 것이 프로젝트 방침이다

검증내용
학교코드 저장·조회자동완성 선택 시 코드·출처가 저장되고, 직접입력이면 둘 다 null
SCHOOL dimension 그룹핑최종학력의 학교코드로 분할되고, 표시명이 학력 행의 학교명과 일치
'기타' 버킷직접입력·학력 없음이 하나의 '기타' 그룹으로 합산
topN 접기상한 초과 학교 + 미매칭이 '기타'로 합산
최종학력 선택레벨 동률이면 학교코드가 있는 행을 우선
PII 파기학력 파기 동작에 회귀 없음

전체 리그레션은 실행하지 않았다(변경 범위만 검증하는 프로젝트 정책).

주의 사항

#항목영향
1기존 지원서의 학교 매칭 정보가 사라진다이미 저장된 school_id는 읽지 않는다. 과거 공고의 학교별 통계는 전부 '기타'로 집계된다
2school_id 컬럼이 DB 에 남는다ddl-auto: update는 컬럼을 지우지 않는다. 운영 반영 시 수동 DROP 이 필요하다
3프론트가 아직 schoolId를 보낸다알 수 없는 필드는 무시되므로 저장은 되지만 학교코드가 늘 null 이다. S3 완료 전까지 학교별 통계가 채워지지 않는다
4대학 API 에 학교코드가 없으면 학교명이 코드가 된다학교명 표기가 바뀌면 통계 그룹이 갈라진다. 인증키 발급 후 확인이 필요하다
