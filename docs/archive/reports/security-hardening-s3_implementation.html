#항목조치
1비밀번호를 바꿔도 탈취된 다른 세션이 유지됨로그인 시 SessionRegistry에 등록합니다. 변경은 다른 세션, 재설정은 모든 세션을 UserSessionRevoker로 만료합니다. ConcurrentSessionFilter가 다음 요청에 401을 줍니다
2세션 principal에 BCrypt 해시가 남음CustomUserDetails가 CredentialsContainer를 구현해 인증 후 지웁니다. loginId 기준 equals도 추가했습니다(레지스트리 키)
372바이트 초과 새 비밀번호에서 encode 예외 → 500 (실측)가입·재설정·변경 요청 DTO에 @AssertTrue 검증을 두어 400을 돌려줍니다. 로그인은 matches가 false라 영향이 없습니다(실측)
4외부 API 오류 로그에 API 키 노출(ResourceAccessException 메시지에 쿼리 포함 URL)juso·NEIS·대학 2종 로그를 예외 종류만 남기도록 바꿨습니다
5주소·학교 검색어가 URI 템플릿으로 해석(중괄호 → 500)juso·NEIS 검색어를 URI 변수로 넘깁니다
6메일 제목에 치환 값의 CR/LF가 섞일 수 있음MessageRenderer.renderSubject가 제어문자를 공백으로 바꿉니다(관리자 발송·시스템 메일)
7공고 contentHtml 미정제 응답관리자·공개 상세 응답에서 HtmlTextUtils.sanitize
8전형결과 업로드 템플릿의 이름 열 수식 prefix파서가 읽지 않는 열이라 ' 이스케이프를 적용합니다. 면접 일정은 성명을 대조하므로 제외
9xlsx 압축 폭탄으로 힙 소진 가능PoiSecurityConfig: ZipSecureFile 항목 상한 20MB

11폐지 메타데이터 교체 API의 무제한 목록·제어문자목록 20개 상한, 파일명·content type 제어문자 거부(테스트 픽스처가 써서 제거하지 않음)
12NICE 보관소 무제한(비로그인 공개 경로)상한 10만 건. 가득 차면 만료분을 정리하고, 그래도 가득이면 400
13UMS 수신 서버: 무제한 큐·줄 길이·발신지 무제한대기 연결 16, 한 줄 1024자, 허용 IP 목록(RECRUIT_MESSAGE_REPORT_ALLOWED_IPS, 비면 모두 허용)

17비밀번호 정책이 길이(8자)뿐KISA 권고: 영문 대·소문자·숫자·특수문자 중 2종류 이상 10자, 3종류 이상 8자. 서버 PasswordPolicy(가입·재설정·변경 DTO)와 FE common/passwordPolicy.ts(가입·재설정·마이페이지)가 같은 규칙

결정 로그

#결정근거
1세션 만료는 Spring Security SessionRegistry로 구현DB 컬럼(비밀번호 변경 시각)을 추가하면 운영 DDL과 요청마다 DB 조회가 필요합니다. 레지스트리는 기존 in-memory 세션 전제와 맞습니다
272바이트 검증은 요청 DTO의 @AssertTrue기존 Bean Validation 400 흐름을 그대로 타고 새 클래스가 필요 없습니다
3API 키 파라미터는 URI 변수로 바꾸지 않고 검색어만 바꿈키 인코딩 방식이 바뀌면 외부 인증이 깨질 수 있습니다(대학 API 주석의 인코딩 키 이슈)
4폐지 API는 제거하지 않고 입력만 제한테스트 7개가 메타데이터 행 픽스처로 씁니다. 제거는 별도 정리 작업
5AES 평문 charset은 그대로 둠운영 JVM 기본 charset이 UTF-8이 아니었다면 명시하는 순간 기존 암호문이 깨집니다. 운영 charset 확인 뒤 결정
6프록시 헤더 신뢰는 코드 기본값을 바꾸지 않음프록시 구성을 레포에서 확인할 수 없습니다. SERVER_FORWARD_HEADERS_STRATEGY 환경변수로 켤 수 있어 운영 권고로 남깁니다
