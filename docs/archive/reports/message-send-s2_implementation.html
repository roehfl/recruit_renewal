요약

메시지 종류와 조건을 고르면 서버가 수신 대상과 수신자별 변수 값을 내려주고, 발송 화면(/admin/messages)에서 템플릿을 불러와 작성하며 수신자별 메일·휴대폰 미리보기를 볼 수 있게 했습니다.

치환·SMS byte 규칙은 서버 MessageRenderer와 프론트 messageRender.ts가 같은 규칙·같은 테스트 예시로 구현합니다(코드포인트 기준 byte, 줄바꿈 LF 통일, 1회 치환).

작업 묶음마다 스펙·품질 리뷰를 거쳤고, 최종 리뷰에서 나온 Important 1건(숨은 입력란에 변수 칩이 들어가는 문제)까지 고친 뒤 재승인을 받았습니다. 실제 발송·테스트 발송은 S3입니다.

리뷰 반영 (결정 로그)

#결정근거
1대상 쿼리를 메시지 전용 MessageTargetRepository에 둠다른 카드 소유 리포지토리를 건드리지 않음
2마감 임박 부가정보를 lastSavedAt → draftStartedAt(생성 시각)섹션 저장은 지원서 수정 시각을 바꾸지 않아 "마지막 저장"이 부정확
3마감 판정에 기존 ReceptionStatus.from 재사용프론트 accepting과 경계 일치
4면접 정렬에 면접 id 추가, 조 정렬은 숫자 파싱 없이같은 시각 병행 조가 섞이지 않음, 긴 숫자 조 이름 500 방지
5SMS byte 판정은 SMS 가능한 수신자만, 메일 입력과 계산 분리판정 정확도, 3,000명 입력 성능
6변수 칩은 현재 탭 본문으로 커서 초기화, 꺼진 채널에서는 비활성숨은 메일 본문에 변수가 조용히 들어가던 문제(최종 리뷰 Important)
7치환 값은 자기 속성만 조회, 라벨은 공용 상수 재사용#{constructor} 같은 키 오작동 방지, 백엔드와 같은 라벨 유지
