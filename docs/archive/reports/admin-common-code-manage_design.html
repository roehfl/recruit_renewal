관리자 공통코드(CommonCode) 관리 화면 - 설계

설계 완료 프론트 단독 작성일: 2026-08-28

요약

관리자가 런타임에 공통코드를 등록·수정·비활성화하는 화면 /admin/codes를 설계했다. 현재 CommonCode는 시드 마이그레이션이 없어 이 화면이 유일한 등록 경로가 된다.

백엔드 CRUD API가 Phase 08a에서 이미 완성되어 있어 백엔드 코드·스키마 변경은 없다. 프론트 화면·API 모듈·라우트만 추가한다.

그룹(groupCode) 목록을 담을 테이블이 없으므로, 그룹 자체를 CODE_GROUP 그룹의 코드로 등록하는 자기참조 구조를 택했다. 그룹 행의 description이 이 코드를 어느 화면에서 쓰는지 알려주는 메모 역할을 한다.

삭제는 백엔드에 하드 삭제가 없으므로 active=false soft delete로만 처리하고, 비활성화 시 확인 모달로 영향 범위를 경고한다.

CommonCode 필드: id / groupCode / code / displayName / sortOrder / active / description(500자). groupCode + code는 생성 후 불변이며 유니크 제약(uk_common_code_group_code)이 걸려 있다. 중복 생성은 400으로 반환된다.

검증 결합 그룹은 ApplicationBasicInfoService가 existsByGroupCodeAndCodeAndActiveTrue로 확인한다. 해당 코드를 비활성화하면 그 값을 가진 지원자의 지원서 저장이 실패한다. LANGUAGE_TEST_*는 그룹명이 런타임에 파생되므로 그룹 선택 UI를 고정 목록으로 만들 수 없다.

동작 모델 - 그룹 self-host

그룹 목록을 담는 테이블이 없으므로 그룹 자체를 groupCode = CODE_GROUP인 코드 행으로 등록한다.

groupCodecodedisplayNamedescription (사용 화면 메모)
CODE_GROUPNATIONALITY국적지원서 > 기본정보 국적 셀렉트 · 백엔드 검증 결합
CODE_GROUPLANGUAGE_TEST_ENGLISH영어 시험명지원서 > 어학 시험명 (LANGUAGE_TYPE=ENGLISH 하위)
NATIONALITYKR대한민국(선택)
  • CODE_GROUP도 그룹 셀렉트에 나타나므로 그룹 등록·수정·비활성화를 같은 테이블에서 처리한다. 별도 화면이 필요 없다.
  • 동적 그룹(LANGUAGE_TEST_ENGLISH 등)도 문자열이므로 그대로 등록된다.
  • 사용 화면 메모는 관리자 수기 입력이며 실제 코드와 자동 동기화되지 않는다.

데이터 로딩 흐름

화면 진입→ GET /api/admin/codes (groupCode 없이 1회)→ 전체 코드 메모리 보관→ 그룹 목록 파생→ 테이블 렌더
생성 / 수정 성공→ 전체 재로드→ 그룹 목록 · 테이블 동시 갱신

그룹 셀렉트 항목 = CODE_GROUP 그룹의 코드 목록 ∪ 응답에 실제 존재하는 distinct groupCode. 후자에만 있는 그룹은 (미등록)으로 표시해 등록을 유도한다. 그룹 전환·키워드 검색·비활성 필터는 모두 클라이언트 측 처리로 재요청하지 않는다.

화면 사양

툴바

  • 그룹 셀렉트(a-select, show-search) — 표시명과 그룹코드를 함께 표기
  • 키워드 입력 — code/displayName 부분일치, 클라이언트 필터
  • 비활성 포함 체크박스 — 기본 ON
  • 코드 등록 버튼 — 현재 그룹을 groupCode로 프리필

테이블 (a-table)

  • 컬럼: 정렬순서 / 코드 / 표시명 / 설명 / 상태 / 액션
  • 선택 그룹이 CODE_GROUP이면 설명 컬럼 헤더를 사용 화면 포함 라벨로 변경
  • 비활성 행은 흐리게 + 비활성 태그
  • 액션: 수정 / 비활성화(활성 행) / 활성화(비활성 행)

안내 영역 표시 규칙

조건표시
CODE_GROUP에 등록됨 + description 있음사용 화면 칩 + 메모 + 메모 수정 버튼
등록됨 + description 없음사용 화면 미기재 안내 + 메모 작성 버튼

선택 그룹이 검증 결합 그룹경고 배너 — 비활성화 시 지원자 저장 실패

수정 모드에는 그룹코드와 코드가 생성 후 변경 불가라는 힌트를 노출한다. 대상이 CODE_GROUP이면 설명 필드 라벨에 사용 화면을 병기하고 예시 힌트를 보여준다. 중복 코드 등 서버 오류는 getApiErrorMessage로 백엔드 메시지를 그대로 표시한다.

비활성화(삭제) 정책

활성→ 비활성화 + 확인 모달→ 비활성→ 활성화 (확인 없음)→ 활성
대상경고 내용수준
모든 코드 (공통)지원자 선택지에서 즉시 사라짐. 이미 저장된 지원서는 값이 남지만 표시명이 비어 보일 수 있음. 재활성화로 복구 가능안내
검증 결합 그룹의 코드이 코드를 가진 지원자가 지원서를 다시 저장하면 실패함강한 경고
CODE_GROUP의 행(그룹)하위 코드는 계속 동작하며 이 화면 그룹 목록에서만 가려짐주의

하드 삭제는 제공하지 않는다. 백엔드에 삭제 API가 없고, FK가 없어 참조 검사 비용이 크며, 동적 그룹은 검사 대상을 특정할 수 없다.

결정 로그

#결정근거
1삭제는 soft delete(active=false)만 제공백엔드에 하드 삭제 API 없음. 기존 지원서의 코드 참조 보존 및 복구 가능
2그룹을 CODE_GROUP 자기참조로 관리백엔드 변경 0으로 그룹 한글명을 런타임 관리. 동적 그룹도 그대로 수용
3단일 테이블 + 그룹 필터 구조그룹과 코드가 같은 스키마라 한 테이블로 충분. 그룹 CRUD도 같은 화면에서 처리
4비활성화 시 확인 모달 + 경고 문구참조 카운트 API는 동적 그룹 커버 불가 대비 비용 과다
5사용 화면은 CODE_GROUP 행 description에 수기 기재필드가 이미 존재. 프론트 상수 맵이나 백엔드 컬럼 추가 없이 즉시 가능
6sortOrder 기본값은 그룹 내 최대값 + 10중간 삽입 여지 확보
7수정 시 groupCode/code disabled엔티티가 두 필드를 불변으로 강제하고 CommonCodeUpdateRequest에도 없음
