학교 검색 OpenAPI 전환 - S1 백엔드 골격

구현 완료 인증키 대기 작성일: 2026-08-27 (엔드포인트 확정 반영)

요약

지원자 학력 입력의 학교 자동완성을 자체 School 마스터 DB 검색에서 외부 OpenAPI 프록시로 교체했다. 고등학교는 NEIS 학교기본정보를, 전문대학·대학교·대학원은 공공데이터포털 전국대학및전문대학정보표준데이터를 호출한다.

구조는 기존 juso.go.kr 주소 검색 연동(JusoProperties/JusoClientConfig/JusoAddressClient)을 그대로 따랐다. 인증키는 서버 설정에만 두고 프론트에 노출하지 않으며, 키 미설정·외부 장애·파싱 실패는 모두 502로 감춘다.

인증키 발급 전이라 실제 응답 검증은 하지 못했다. 외부 호출 없이 검증 가능한 라우팅·중복제거·오류 매핑만 테스트로 고정했다.

전체 전환은 S1~S4로 나눈다. 이번은 S1(검색 백엔드)까지이며, 학력 스키마 전환(S2)·프론트 연동(S3)·레거시 제거(S4)는 후속이다.

응답 필드

필드타입설명
schoolCodeString외부 학교코드. NEIS는 SD_SCHUL_CODE, 대학은 학교코드(없으면 학교명으로 대체)
schoolNameString학교명
schoolSourceSchoolSourceNEIS | UNIV_INFO | UNIV_DEPT. 코드 체계가 달라 네임스페이스 구분에 쓴다. 학교 검색이 실제로 내보내는 값은 앞의 둘
regionString소재지

기존 응답의 id(School PK, Long)와 schoolType은 제거됐다. 요청 파라미터도 한글 라벨 schoolType에서 enum educationLevel로 바뀌었다.

학교 구분별 라우팅

educationLevel호출 대상필터 값
HIGH_SCHOOLNEIS 학교기본정보SCHUL_KND_SC_NM = 고등학교
COLLEGE전국대학및전문대학정보학교구분 = 전문대학
UNIVERSITY전국대학및전문대학정보학교구분 = 대학교

2026-08-27 데이터셋 교체: 처음 잡았던 전국대학별학과정보는 학과 단위라 학교 목록으로는 맞지 않았다(학교 식별 코드도 제공 항목에 없다). 행 1건이 학교 1곳인 전국대학및전문대학정보로 바꿨다. 학과 데이터셋 호출 코드(UnivDeptSchoolClient)는 전공명 자동완성 후속 검토용으로 남겨뒀고, 학교 검색 경로에서는 호출하지 않는다. 학교구분 실제 값은 서비스키 발급 후 확정해야 한다.

결정 로그

#결정근거
1juso 연동 구조를 그대로 복제외부 OpenAPI 프록시 선례가 이미 있고, 타임아웃·키 은닉·오류 분류 규칙이 검증돼 있다
2고정 스키마 record 대신 JsonNode 순회로 파싱NEIS는 정상/오류 응답의 최상위 구조가 다르고, 대학 표준데이터는 행 필드명이 확정 전이라 스키마를 고정하기 이르다
3학교 검색 데이터셋을 tn_pubr_public_univ_info_api(전국대학및전문대학정보)로 확정먼저 잡았던 학과 데이터셋은 행이 학과라 학교 목록으로 부적합하고 학교 식별 코드도 없다. 학교 데이터셋은 행 1건이 학교 1곳이라 중복제거도 필요 없다
7대학원도 대학교 목록을 그대로 사용대학원 전용 학교 목록이 없다. 지원자는 "○○대학교"로 입력하므로 실사용에 문제가 없다
8학과 데이터셋 호출 코드를 남겨둠사용자 지시. 학력 입력의 majorName 은 현재 자유 입력이라 전공명 자동완성에 재활용할 여지가 있다
4대학 API의 page-size를 100으로(자동완성 상한 20보다 크게)학과 단위 데이터라 같은 학교가 여러 행으로 온다. 중복제거 후에도 결과가 남아야 한다
5NEIS INFO-200은 오류가 아닌 빈 결과검색 결과 없음은 정상 흐름이다. 502로 올리면 사용자가 장애로 오인한다
6파라미터를 educationLevel enum으로 교체기존에는 프론트가 한글 라벨을 그대로 보내 DB 값과 문자열 일치에 의존했다. enum이면 오타·라벨 변경에 깨지지 않는다

미결 사항

#질문현재 입장
1학교명 검색 파라미터(schoolNm)를 상위 API 가 실제로 필터로 받는가무시될 수 있어 응답에서 학교명 포함 여부를 한 번 더 거른다. 필터가 먹지 않으면 첫 페이지만 조회되므로 실측 후 조정한다
2행 필드명(schoolNm/schoolGbn/schoolCd/ctprvnNm)이 실제와 일치하는가클라이언트 상수로 모아뒀다. 다르면 상수만 고치면 된다
3대학원·전문대학이 같은 데이터셋에 포함되는가포함 전제로 라우팅했다. 별도 데이터셋이면 클라이언트를 하나 더 둔다
4학교 식별 코드가 응답에 있는가포털의 제공 항목 목록에는 없다. 없으면 학교명이 코드가 되어 학교별 통계 그룹 키가 학교명 문자열이 된다
5일일 호출 쿼터 대응이 필요한가현재 캐싱 없음. 실사용 호출량 확인 후 결정한다
6서비스키를 인코딩/디코딩 중 무엇으로 넣는가디코딩 키를 넣는다. 인코딩 키를 넣으면 URI 빌더가 다시 인코딩해 인증이 깨진다
7DMZ 프록시가 프리픽스 뒤 경로를 그대로 전달하는가그대로 전달한다고 보고 /neis/hub/schoolInfo, /gov/openapi/tn_pubr_public_univ_info_api 로 구성했다. 프록시가 경로를 다르게 매핑하면 환경변수로 덮어쓴다

테스트검증 내용
검색어가 비면 외부호출 없이 빈 목록공백 입력 시 두 클라이언트 모두 호출되지 않는다
고등학교는 NEIS로 라우팅HIGH_SCHOOL이면 NEIS만 호출하고 schoolSource가 NEIS
대학·대학원은 학교구분값으로 라우팅전문대학/대학교/대학원 값이 각각 전달되고, 석사·박사는 같은 값을 쓴다
같은 학교코드는 한 번만 남는다학과 단위 중복 행이 학교 단위로 접힌다
학교구분 누락은 400필수 파라미터 검증
인증키 미설정이면 502설정 누락이 상위 의존 장애로 매핑된다

전체 리그레션은 실행하지 않았다(변경 범위만 검증하는 프로젝트 정책). 실제 외부 API 응답 파싱은 인증키가 없어 검증하지 못했다.
