구현 완료 작성일: 2026-09-18

요약

관리자 면접 스케줄링 화면의 입력을 엑셀 업로드로만 받도록 구현했습니다. 조회 표, 업로드 양식, 다운로드 파일이 같은 한글 9열 양식을 씁니다.

업로드는 선택한 면접단계의 기존 스케줄을 파일 내용으로 통째로 교체하고 바로 확정(CONFIRMED)합니다. 오류가 1건이라도 있으면 아무것도 반영하지 않고 행별 오류를 돌려줍니다.

요청에 따라 면접 도메인에서 종료 시각(endDateTime)을 없애고 도착 시각(arrivalDateTime)을 추가했습니다. 시간 겹침 검사는 "같은 면접 시각" 기준으로 바뀌었습니다.

백엔드 36개 테스트 클래스(419건)와 프론트 type-check가 통과했습니다. 배포 전 운영 DB 컬럼 삭제 작업이 필요합니다.

엑셀 행 → 도메인 매핑

조 = 면접 1건

엑셀 1행 = 지원자 1명
  조(1..N)          ──► Interview.groupName
  일자 + 면접시간    ──► Interview.startDateTime
  일자 + 도착시간    ──► Interview.arrivalDateTime
  장소              ──► Interview.locationName
  면접관(이름(ID),…) ──► InterviewParticipant(INTERVIEWER)
  면접순서           ──► InterviewParticipant(CANDIDATE).sortOrder
  수험번호 / 성명     ──► JobApplication.id / 성명 스냅샷 대조
  • 같은 조의 행은 일자·장소·도착시간·면접시간·면접관이 같아야 합니다.
  • 조와 면접순서는 1부터 빠짐없이 이어집니다.

결정 로그

#결정근거
1업로드 = 단계 전체 교체 + 즉시 확정다운로드 → 수정 → 업로드 왕복이 자연스럽고, 화면에 확정 버튼이 없음(사용자 결정)
2한 행 = 지원자, 조 = 면접 1건, 같은 조는 일자·장소·시각·면접관 동일사용자 결정. 면접관은 면접(조) 단위로 저장되는 모델과 일치
3도메인에서 종료 시각 삭제사용자 결정. 엑셀에 종료 시각이 없음
4시간 겹침 검사를 "같은 면접 시각"으로 변경종료 시각이 없어 범위 겹침을 판단할 수 없음
5면접관 칸은 이름(로그인ID)동명이인 방지, 다운로드 파일을 그대로 재업로드 가능(사용자 결정)
6다운로드는 마지막 검색 조건으로, 표가 비면 템플릿화면 표와 받은 파일이 일치해야 함
7export 감사 행위 분류는 기존 EXPORT_INTERVIEWS 재사용새 enum 없이 같은 "면접 데이터 반출"로 분류, datasetType으로 구분

운영 작업

배포 전 필수 DB 컬럼 정리

  • 스키마는 ddl-auto=update라 컬럼을 지우지 않습니다. 기존 DB에는 NOT NULL인 interview.end_date_time이 남아 새 면접 저장이 실패합니다.
  • 배포 전 인덱스 idx_interview_time_range와 컬럼 interview.end_date_time을 삭제해야 합니다. 새 컬럼 arrival_date_time과 새 인덱스는 자동 생성됩니다.
