구현 완료 브라우저 검증 완료 작성일: 2026-09-02

요약

공고별 지원서 설정 화면 /admin/application-forms/:jobPostingId 를 탭 호스트 + 탭 2개로 구현했다. 탭은 MenuManageView 의 밑줄형 site-tabs 패턴을 그대로 쓴다.

[지원서 양식] 탭은 S1에서 만든 전용 엔드포인트로 섹션 사용/필수를 저장한다. [폼 구성] 탭은 시안 A(팔레트 + 페이지 캔버스)를 드래그앤드롭으로 구현했고, 미배치 서랍이 비어야만 저장 버튼이 열린다.

드래그앤드롭은 신규 의존성 없이 HTML5 네이티브 DnD 로 구현했다.

S1에서 생긴 "양식을 편집할 화면이 없다"는 기능 공백이 닫혔다.

/admin/application-forms/:jobPostingId          AdminApplicationFormDetailView
  ├─ 헤더: 공고 제목 · 상태 배지 · 접수기간 · [공고 상세] 버튼
  ├─ site-tabs: [지원서 양식] [폼 구성]         (MenuManageView 와 동일 규약)
  │
  ├─ ApplicationFormConfigTab                   POST .../application-form-config
  │     섹션 7종 사용/필수 체크박스 그리드
  │
  └─ ApplicationFormLayoutTab                   GET·POST .../application-form-layout
        ├─ 좌: 미배치 서랍 + 비활성 섹션
        └─ 우: 페이지 카드(제목·설명·↑↓·삭제) + 칩 DnD + [페이지 추가]
  • 탭 전환 시 :key 를 바꿔 리마운트한다. 양식 변경이 폼 구성의 활성 섹션 집합을 바꾸므로 항상 최신 상태를 다시 읽어야 한다.
  • 양식 저장 성공 시 공고 상세를 재조회하고 세대 값을 올려, 이후 폼 구성 탭이 새 활성 섹션으로 열린다.
  • 편집 가능 여부는 클라이언트 시계로 계산하지 않고 서버가 내려준 status + receptionStatus === 'UPCOMING' 로 판단한다. 백엔드 가드와 같은 의미다.

제목 100자 · 설명 500자 초과는 저장 직전 한 번 더 확인한다. 서버 검증과 동일한 한계값이다.

저장 이후 섹션이 꺼진 경우

저장된 레이아웃에 지금은 비활성인 섹션이 남아 있으면(질문 삭제 등) 로드 시 그 항목을 제외하고 경고 배너로 알린다. 저장하면 정리된 상태가 반영된다. 설계 단계에서 지목한 RELAYOUT_REQUIRED 상황의 반대 방향 케이스다.

드래그앤드롭

  • HTML5 네이티브 DnD(draggable · dragstart · drop). 라이브러리를 추가하지 않았다.
  • 페이지 카드에 드롭하면 끝에 추가, 칩 위에 드롭하면 그 앞에 삽입한다.
  • 팔레트에 드롭하면 미배치로 되돌린다.
  • 같은 페이지 안에서 앞 항목을 뒤로 옮길 때 제거로 인덱스가 당겨지는 것을 보정한다.
  • 페이지 삭제 시 그 페이지의 항목은 사라지지 않고 팔레트로 돌아간다.

저장 payload

pages[i] → { pageNo: i+1, sortOrder: i, title, description(빈 문자열이면 null),
             items: [{ sectionType, sortOrder: j }] }

pageNo 와 sortOrder 를 저장 시점에 다시 부여해 중복·구멍을 원천 차단한다.

범위를 넘은 변경 1건

공고 상세 화면에 "지원서 설정" 버튼을 추가했다. 설계상 진입 경로는 S2 현황판이지만, S2 전까지는 URL 직접 입력 외에 화면에 닿을 방법이 없어 S3의 목적(기능 공백 해소) 자체가 성립하지 않기 때문이다. route meta activeMenuPath 도 잠정적으로 /admin/job-postings 를 가리킨다. S2에서 현황판 메뉴가 생기면 두 값 모두 정리 대상이다.

알려진 한계

#항목현재 상태
1 진입 경로가 잠정적이다 공고 상세 버튼으로만 들어간다. S2에서 현황판 메뉴가 생기면 activeMenuPath 와 함께 정리한다
2 드래그앤드롭에 키보드 대안이 없다 페이지 순서는 ↑↓ 버튼으로 가능하지만 항목 이동은 드래그 전용이다. 접근성 보완은 후속 과제
3 동시편집 보호가 없다 레이아웃 저장은 전체 치환이며 낙관적 잠금이 없다. 두 관리자가 동시에 저장하면 나중 저장이 이긴다
4 프론트 단위 테스트가 없다 브라우저 수동 검증으로 대체했다. 저장 payload 변환과 드롭 인덱스 보정은 단위 테스트 대상으로 적합하다

S2(지원서 설정 현황판) 로 넘어간다. 신규 요약 API(GET /admin/application-forms)와 group by 집계, configState 계산이 백엔드 작업의 핵심이다.
