전 시스템 보안 점검 결과 중 설정 변경과 버전 업그레이드로 해결되는 항목을 1차로 조치했습니다.

개발용 기능(H2 콘솔, API 문서)은 기본적으로 끄고 로컬에서만 켜도록 했습니다. 설정 누락이 조용한 위험으로 이어지던 값(메시지 게이트웨이, CORS 허용 출처, 세션 쿠키)은 안전한 기본값을 두거나 기동 실패로 바꿨습니다.

부서 권한 매핑의 와일드카드 권한 상승을 막았습니다. Spring Boot 4.0.8, Tomcat 11.0.26 등으로 올려 알려진 CVE를 해소했습니다.

2차(시도 횟수 제한, 첨부 내용 검사, CSRF, 기본 정책 전환)와 3차(Low 항목)가 남아 있습니다.

결정 로그

#결정근거
1개발용 기능은 기본 꺼짐, 로컬에서만 명시적으로 켬기존 NICE_MOCK_ENABLED·AUDIT_ALLOW_FALLBACK_SECRET와 같은 fail-safe 관례. 프로파일이 없어 환경을 구분할 수 없음
2게이트웨이는 기본값 없이 필수누락을 조용한 목업 동작이 아니라 기동 실패로 드러내기 위해(NICE Mock 가드와 같은 방식)
3CORS 기본값은 로컬이 아니라 운영 주소운영에서 설정을 빠뜨려도 올바르게 동작하고, 빠뜨린 쪽이 개발 환경이면 403으로 바로 드러남
4SameSite는 Strict가 아니라 Lax메일 링크로 들어올 때 로그인이 유지되어야 하고, NICE 콜백 설계(교차 사이트 요청에 쿠키 없음)가 이미 Lax를 전제로 함
5부서명의 %·_를 거부하지 않고 locate로 판정밑줄이 든 실제 부서명을 계속 등록할 수 있고, 기존 부분일치 의미를 그대로 유지
6Tomcat 버전은 ext['tomcat.version']으로 따로 지정Boot 4.0.8이 관리하는 11.0.24에 CVE-2026-65182가 남아 있음. Boot가 11.0.25 이상을 관리하면 이 지정을 지움
