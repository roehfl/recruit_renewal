시스템 자동발송 메일 — 가입 이메일 인증 · 비밀번호 재발급 · 제출 완료 안내

구현 완료 미커밋 작성일: 2026-09-23

요약

사내 TR 게이트웨이로 메일 실발송·결과 수신이 확인되어, 목업이던 가입 이메일 인증과 비밀번호 재발급을 실제 메일 연동으로 바꾸고 지원서 제출·재제출 완료 안내 메일을 새로 추가했다.

비밀번호 재발급은 임시 비밀번호·재설정 링크 방식을 폐지하고 "인증번호 확인 → 그 자리에서 새 비밀번호 설정" 방식으로 대체했다. 3종 메일 이력은 기존 message_send·message_recipient를 재사용하며 발송 구분 origin(ADMIN/SYSTEM)을 추가했다.

인증번호는 숫자 6자리·유효 5분·5회 오류·재발송 60초·확인 후 10분 규칙을 따르며, DB와 운영 로그에는 남기지 않는다(세션에는 SHA-256 해시만 저장).

백엔드·프론트 구현과 대상 범위 테스트, 문서 갱신까지 마쳤으며, 커밋 전 최종 리뷰에서 enum 컬럼 확장 관련 Critical 이슈를 발견해 운영 DDL에 반영했다.

결정 로그

#결정근거
1비밀번호 재발급을 인증번호 확인 후 즉시 새 비밀번호 설정 방식으로 통일기존 카드의 "임시 비밀번호·재설정 링크" 결정을 대체, 사용자 흐름 단순화
2인증번호는 세션에만 SHA-256 해시로 저장, DB 테이블 없음인증번호가 DB·운영 로그에 남지 않도록 하기 위함
3로컬 목업 게이트웨이(gateway=logging)만 메일 본문(text)을 로그에 남김로컬 환경에서 인증번호 확인 목적, TRNodeMessageGateway(운영)는 본문 미기록 유지
4가입 인증 만료 시 화면에서 재인증 단계로 자동 복귀10분 경과로 가입이 "이메일 인증이 필요합니다."로 실패해도 새로고침 없이 재인증 가능하게 함
5가입 인증·비밀번호 재설정 이력 수신자 행의 파기 정책은 이번 범위에서 제외지원서와 연결되지 않는 행의 처리 기준은 별도로 정할 필요가 있어 사용자가 보류 결정
6제출 완료 메일은 별도 sendAfterCommit 경로 없이 리스너 내부에서 동기 디스패치로 처리리스너가 이미 @TransactionalEventListener(AFTER_COMMIT) + @Async로 비동기 실행되므로 추가 이벤트 경유가 불필요
7비밀번호 재발급 미가입 이메일은 404로 응답(계정 열거 가능성 감수)기존 카드의 결정을 유지

#항목현재 입장
1운영 배포 전 enum 컬럼 확장 DDL 반영이 필요한가?필수. 최종 리뷰에서 발견된 Critical 이슈 — H2·MariaDB 모두 message_type 컬럼이 네이티브 ENUM이라 ddl-auto: update로는 새 값이 늘지 않아 기동이 실패한다. 운영 DDL(message-send-origin-ddl.sql)에 message_type ENUM 확장을 추가했으며, 새 버전 기동 전 반드시 수동 반영해야 한다.
2운영에서 메일 게이트웨이 설정이 누락되면?목업 게이트웨이(gateway=logging)가 켜져 메일 본문이 로그에 남을 수 있으므로, 운영 설정에 recruit.message.gateway=trnode가 명시돼 있는지 배포 전 확인이 필요하다.
3세션 밖 발송 제한은 없는가?새 세션으로 인증 절차를 반복할 수 있다(범위 외 결정). 비밀번호 재발급 미가입 이메일은 404로 응답해 계정 열거 가능성을 감수하는 기존 결정을 유지한다.
4가입 인증·비밀번호 재설정 이력 수신자 행의 파기 정책은?미정. 지원서와 연결되지 않아 기존 파기 정책 대상이 아니므로 별도로 정해야 한다.
5문서 카드 용량은 여유가 있는가?auth-account.md 카드가 40KB 상한에 근접해 향후 분할이 필요할 것으로 보이며, _index.md도 12KB 상한에 근접했다.
6기존 문서의 DDL 불요 주석이 사실과 다른가?기존 phase-09e-reconciliation-ddl.sql 주석에 "enum은 VARCHAR라 DDL 불요"라는 설명이 있으나, 실제로는 네이티브 ENUM이라 해당 enum 값 추가 시에도 운영 DB 확인이 필요하다. 이번 작업 범위 밖이라 수정하지 않고 보고만 한다.

최종 리뷰 발견·조치 사항

Critical H2·MariaDB 모두 message_type이 네이티브 ENUM 컬럼이라 ddl-auto: update로는 새 값이 늘지 않아 기동이 실패한다 → 운영 DDL에 ENUM 확장 추가, 새 버전 기동 전 반영 필수로 조치.

Minor(조치 완료) verify 요청 동시성 처리, 가입 시 loginId=email 강제, 비밀번호 재설정 이메일 대소문자 처리, 첫 발송 실패 시 인증번호 입력칸 유지.
