구현 완료 front + back 슬라이스 작성일: 2026-08-28

요약

지원서 어학 섹션에서 자유 텍스트로 받던 언어와 시험명을 공통코드(CommonCode) 선택으로 전환했다.

안정 키와 표시명을 분리해 languageCode/testCode(코드)를 추가하고, 기존 languageName/testName은 선택 시점의 표시명 스냅샷으로 유지한다. PDF와 관리자 검색은 표시명을 그대로 쓰므로 무변경이다.

시험명은 언어에 종속되므로 언어별 그룹 LANGUAGE_TEST_{languageCode}로 분리해 연동 선택을 구성했다. 목록에 없는 값은 ETC 선택 후 직접입력으로 받는다.

백엔드 scoped 테스트와 프론트 type-check가 모두 통과했고, api-contract.md의 어학 섹션을 🟢로 갱신했다.

testCodeStringnullable (파기 대상)공통코드 LANGUAGE_TEST_{languageCode} 코드값. 직접입력이면 ETC

기존 필드(scoreOrGrade, conversationalAbility, examDate, expiredDate, issuingOrganization, sortOrder)는 변경 없음. 코드 컬럼을 nullable로 둔 이유는 PII 파기 시 null로 비우기 때문이며, 입력 필수 여부는 LanguageRequest와 서비스 검증이 강제한다.

공통코드 그룹 구조

LANGUAGE_TYPE                  (언어)
├─ ENGLISH        영어
├─ JAPANESE       일본어
├─ CHINESE        중국어
└─ (ETC)          기타(직접입력) — 프론트가 항상 append

LANGUAGE_TEST_ENGLISH          (영어 시험)
├─ TOEIC          TOEIC
├─ TOEIC_SPEAKING TOEIC Speaking
├─ OPIC           OPIc
└─ (ETC)          기타(직접입력)

LANGUAGE_TEST_JAPANESE / LANGUAGE_TEST_CHINESE ... 언어 코드마다 1개 그룹

위 코드값은 예시다. 실제 코드는 관리자 CommonCode API로 등록한다. CommonCode 엔티티에 부모 참조 컬럼이 없어 계층 표현을 그룹 분리로 대체했다.

입력 흐름

언어 select → languageName = displayName 스냅샷 → 시험 그룹 조회 → 시험명 select → testName = displayName 스냅샷
언어 = ETC → 언어 직접입력 노출, 시험명도 ETC 고정 → 시험명 직접입력

언어를 바꾸면 testCode/testName을 초기화한다. 언어 미선택 시 시험명 select는 비활성이다. 저장된 지원서를 다시 열면 항목의 languageCode 기준으로 해당 시험 그룹을 미리 조회해 라벨을 표시한다.

결정 로그

#결정근거
1코드와 표시명을 모두 저장 (컬럼 2개 추가)코드만 저장하면 PDF·관리자 검색에 코드가 노출되고 ETC 직접입력 값을 담을 자리가 없다. 표시명만 저장하면 displayName 변경 시 과거 데이터와 어긋나고 코드 기준 집계가 불가능하다.
2시험명을 언어별 그룹(LANGUAGE_TEST_{languageCode})으로 분리CommonCode에 부모 코드 컬럼이 없다. description에 부모를 넣는 우회보다 그룹 분리가 모델 왜곡이 적다.
3코드값 백엔드 validation은 결합하지 않음같은 섹션의 conversationalAbility, 학력 majorType, 기본정보 veteranType과 동일한 기존 정책을 유지한다.
4ETC 옵션을 프론트에서 하드코딩 append관리자가 그룹마다 ETC를 등록하지 않아도 직접입력이 가능하고, 코드 미등록 그룹에서도 화면이 죽지 않는다.
5코드 시드 데이터를 코드베이스에 추가하지 않음이 프로젝트의 공통코드는 런타임 관리자 관리 대상이며 저장소에 시드 파일이 없다.

미결 사항

#항목현재 입장
1공통코드 그룹·코드 등록 주체와 시점관리자 CommonCode API로 등록해야 드롭다운이 비지 않는다. 등록 전에는 기타(직접입력)만 노출된다.
2운영 DB 컬럼 추가개발 H2는 ddl-auto로 자동 반영. 운영 MariaDB는 application_language에 language_code, test_code ALTER ADD가 필요하다.
3코드값 존재 검증 결합 여부기존 정책대로 미결합. 코드 오염이 문제되면 어학·학력·기본정보를 함께 다루는 별도 슬라이스로 처리한다.
4PDF의 conversationalAbility 코드 노출이번 슬라이스 이전부터 존재하던 사항. 라벨 변환은 범위 외로 남겼다.
