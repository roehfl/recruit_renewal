구현 완료 미커밋 작성일: 2026-09-19

요약

발송 화면에서 인사팀 담당자에게 테스트 발송(동기, 제목·문자 앞 [테스트])을 하고, 확인 모달을 거쳐 최대 3,000명에게 실제 발송을 접수할 수 있게 했습니다.

접수는 커밋 후 비동기로 처리하며, 같은 내용의 수신자를 최대 10명씩 묶어 게이트웨이를 1회 호출합니다(변수로 내용이 달라지면 1명당 1회). 치환은 요청 시점에 하고 결과는 이벤트로 넘기며, DB에는 원문과 AES 암호화한 연락처만 남깁니다.

게이트웨이는 사내 스펙 미정이라 인터페이스 + 로그 목업(마스킹)입니다. 작업 묶음별 스펙·품질 리뷰와 S3 전체 최종 리뷰(판정: 병합 가능)를 거쳤고, 지적 사항은 반영했습니다.

상태 전이

발송 접수

검증·재조회·교집합·치환→ SENDING→ 커밋 후 @Async, 발송 단위별 호출·기록→ COMPLETED

수신자 채널

PENDING→ 게이트웨이 결과→ SENT / FAILED
접수 시 판정→ SKIPPED CHANNEL_OFF · NO_CONTACT · INVALID_CONTACT

실패 사유는 게이트웨이가 준 코드를 저장하고, 호출 예외·null 결과·빈 사유는 GATEWAY_ERROR. 접수 직후 서버가 내려가면 SENDING/PENDING으로 남고 자동 재개하지 않습니다.

검증 및 비즈니스 규칙

규칙설명
대상 확정발송 시 조건으로 재조회해 요청한 applicationIds와 교집합. 빠진 인원은 excludedCount로 알림
인원 상한최대 3,000명(recruit.message.max-recipients), 넘으면 400
SMS 길이치환 결과 2,000byte 초과 수신자가 있으면 400(수험번호로 표시, 이름 미노출)
발송 단위채널·제목·본문·SMS 구분이 같은 수신자 최대 10명, 메일 먼저. 단위 결과를 전원에게 적용
메일 개별 발송메일 구현체는 단위 안에서도 수신자마다 따로 보냄(To 개별 또는 BCC)
테스트 발송미리보기 수신자가 현재 대상이어야 함, 수신자 1~5명, 동기 처리 후 결과 즉시 반환
개인정보연락처 AES 저장, 게이트웨이 로그는 마스킹·본문 미기록, 예외 메시지 미기록
화면 차단조회 중·조회 실패·대상 0명·채널 전부 제외·허용 안 된 변수·SMS 초과 시 발송·테스트 버튼 비활성, 사유 표시

리뷰 반영 (결정 로그)

#결정근거
1치환을 요청 시점에 하고 결과를 이벤트(메모리)로 디스패처에 전달디스패치 때 대상 재해석·조건 재검증이 필요 없음(S2 최종 리뷰 선행 과제 해소)
2@EnableAsync만 두고 부트 기본 실행기 사용새 Executor 빈이 기본 실행기를 대체해 다른 비동기 작업에 영향 주는 것 방지
3MessageDispatchRecorder는 REQUIRED 전파비동기에선 호출마다 새 트랜잭션, 테스트 발송은 요청 트랜잭션 합류
4발송 요청이 응답 없이 끝나면 모달을 닫고 "발송 이력 확인" 안내멱등키가 없어 재시도가 중복 발송이 될 수 있음
5테스트 발송 중 내용이 바뀌면 늦은 응답 무시(testVersion)테스트 안 한 내용이 테스트 완료로 표시되던 문제(리뷰 Important)
6미리보기 스크롤 고정 제거아래 테스트 발송 카드를 가림(리뷰 Important)
7테스트 수신자 저장값 재검사·중복 연락처 차단옛 형식·손댄 저장값으로 400, 같은 사람에게 두 번 발송 방지
8메일 게이트웨이 계약에 수신자별 개별 발송, 실패 사유에 주소·번호 금지 명시실제 SMTP 연동 시 지원자 간 주소 노출·평문 사유 저장 방지(최종 리뷰 Important)
9빈 실패 사유를 GATEWAY_ERROR로 채움사유 없는 FAILED 방지
10트랜잭션 없는 흐름 테스트 MessageSendAsyncFlowTest 추가기존 테스트는 롤백되어 커밋 후 비동기 경로를 증명하지 못함(최종 리뷰 Important)
