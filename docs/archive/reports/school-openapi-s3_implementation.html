요약

지원자 학력 입력 화면을 S1·S2 로 바뀐 계약에 맞췄다. 학교 검색은 한글 라벨 대신 educationLevel enum 을 보내고, 결과는 schoolCode·schoolSource 로 받는다.

학력 저장 payload 의 schoolId 도 schoolCode·schoolSource 로 교체했다. 이로써 S1 이후 끊겨 있던 학교 검색이 다시 동작한다.

외부 API 는 장애·지연이 있을 수 있어, 검색 실패와 결과 없음을 각각 안내하고 직접 입력으로 진행할 수 있게 했다.

직접 입력으로 학교명을 고치면 앞서 고른 학교코드를 버린다. 코드와 학교명이 어긋난 채 저장되면 통계 그룹이 잘못 묶이기 때문이다.

학교 찾기 모달 동작

학교 구분 선택 → 학교명 검색 GET /api/schools → 목록에서 선택 코드·출처 보관 → 확인 학력 행에 반영

학교 구분을 고르지 않고 검색하면 경고만 띄우고 외부 호출을 하지 않는다. 검색으로 학교를 고른 뒤 직접 입력란을 수정하면 코드가 해제되어 직접 입력과 같은 상태가 된다.

결정 로그

#결정근거
1학교 구분 옵션의 검색용 라벨(searchType)을 제거백엔드가 enum 을 받으므로 표시 라벨과 검색 값을 분리할 이유가 사라졌다. 라벨은 화면 표기만 담당한다
2검색 실패를 경고로 처리하고 직접 입력을 유도외부 API 장애가 지원서 작성 자체를 막으면 안 된다. 학교명은 직접 입력으로도 저장할 수 있다
3직접 입력 시 학교코드를 해제코드는 통계 그룹 키다. 코드는 A 학교인데 이름만 B 로 바꾼 데이터가 저장되면 집계가 틀어진다
4지역이 없으면 괄호를 표시하지 않음외부 API 는 지역이 비어 올 수 있다. 기존 렌더링은 빈 괄호가 남는다
