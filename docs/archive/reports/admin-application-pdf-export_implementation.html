admin 지원서 PDF 저장 / A4 출력 / 일괄 다운로드 — 구현

S1~S5 구현 완료 테스트 60건 통과 런타임 검증 미실시 작성일: 2026-09-09

요약

관리자 지원서 상세를 A4 PDF로 저장하고, 목록에서 선택한 지원서를 zip으로 일괄 다운로드한다. 단건·일괄 모두 백엔드 openhtmltopdf 단일 경로로 처리한다.

Phase 07e가 deferred 처리했던 batch/zip · 학기별 성적 상세표 · 사진 binary embed 세 항목을 모두 회수했다. 표시 모델을 Field(label, value)에서 Section(columns, rows)로 재설계해 관리자 화면과 같은 가로 표를 렌더한다.

작업 중 기존 결함 3건을 발견해 함께 고쳤다: 엑셀 export 필터 불일치, 목록 서버 페이징 미연결, blob 다운로드 오류 메시지 손실.

백엔드 4개(S1~S3, S5) + 프론트 1개(S4) slice를 모두 구현했고 테스트 60건이 통과한다. 브라우저 런타임 검증은 실시하지 못했다.

설계에 없던 추가 작업

enum 한글 라벨 매핑

구현 중 발견

섹션 DTO가 enum을 그대로 노출하고 기존 str()이 enumValue.name()을 반환해, PDF에 HIGH_SCHOOL·MASTER_SERGEANT 같은 영문이 출력되고 있었다. 화면은 프론트 getLabel()로 변환하지만 백엔드에는 대응물이 없었다.

ApplicationPdfLabels를 신규 추가해 PDF 전용으로 격리했다. 도메인 enum은 수정하지 않았다(다른 경로에 영향을 주지 않기 위함). 국적·장애 등급/유형처럼 공통코드 기반 값은 CommonCodeService로 조회한다.

PDF 다운로드 타임아웃

구현 중 발견

프론트 apiClient의 기본 timeout이 10초였다. 일괄 20건은 렌더에 그 이상 걸릴 수 있어 그대로 두면 반드시 타임아웃이 난다. 요청별 timeout(단건 30초 / 일괄 120초)을 지정했다.

함께 고친 기존 결함

#결함증상조치
1 엑셀 export 필터 불일치 목록 조회는 검색 조건 17개를 지원하는데 export는 3개(jobPostingId/jobPositionId/status)만 받았다. 화면에서 이름으로 검색한 뒤 엑셀을 받으면 필터가 빠진 전체 결과가 내려가 PII가 의도보다 많이 반출됐다. 조건 생성을 AdminApplicationSearchConditionFactory로, 조회 절을 ADMIN_SEARCH_WHERE 상수로 공유 (S5)
2 목록 서버 페이징 미연결 프론트가 page를 넘기지 않아 항상 첫 20건만 조회하고, 화면은 그것을 pageSize: 10으로 두 페이지에 나눠 보여줬다. 21건째부터는 화면에 나타나지 않았다. loadApplications(page) 분리 + @change 서버 재조회. pageSize를 20으로 맞춰 일괄 상한과 일치시킴
3 blob 다운로드 오류 메시지 손실 responseType: 'blob' 요청은 오류 응답 본문도 Blob으로 와서 getApiErrorMessage가 서버 메시지를 꺼내지 못한다. 상한 초과 안내가 표시되지 않았다. getBlobErrorMessage를 공용 모듈에 추가

범위 밖이지만 보고만 하고 수정하지 않은 것 — 프론트 라벨 테이블 오타(ENFOLLED vs 백엔드 ENROLLED)로 화면에서 "재학"이 영문으로 표시된다. 백엔드 PDF는 정상 처리한다. careerDescriptionDownload와 전형결과 엑셀에도 결함 3번과 같은 문제가 남아 있다.

일괄 다운로드 처리 순서

중복 id 제거 → 20건 상한 검증(초과 시 400)
  → temp zip 파일에 순차 렌더
  → 담긴 지원서마다 감사 기록
  → StreamingResponseBody 전송 시작
  → 전송 완료 후 temp 삭제
렌더 완료→ 감사 기록→ 200 전송 시작

감사까지 끝낸 뒤에 전송을 시작한다. 스트리밍이 시작되면 이미 200이 나가 오류 상태코드로 되돌릴 수 없기 때문이다. 감사 실패 시 temp를 지우고 예외를 전파해 응답이 나가지 않는다(egress fail-close, 기존 export 규약과 동일).

CSS 지원 관련 확인 사항

  • word-break: break-all은 openhtmltopdf가 해석하지 않는다. 긴 이메일이 셀 경계를 넘어 그려지던 문제를 word-wrap: break-word로 해결했다.
  • table-layout: fixed가 없으면 긴 무공백 문자열 하나가 표를 밀어 폭을 초과시킨다. openhtmltopdf는 초과분을 축소하지 않고 잘라내므로 필수다.
  • page-break-inside: avoid는 정상 동작한다. 페이지 바꿈 두 방식의 결과가 같아 보였던 것은 섹션이 페이지 경계에 걸리지 않았기 때문이며, 표를 22행으로 키우자 4페이지 대 5페이지로 갈렸다.

테스트가 잡아낸 회귀 3건

  • 렌더러 context 누락 — basicInfo를 Thymeleaf context에 넣지 않아 기본정보 표가 통째로 사라졌다. 보안 하드닝 테스트가 잡았다.
  • fallback 동작 손상 — BasicInfo row가 없을 때 Applicant 값으로 fallback하는 Phase 07e 동작을 제거할 뻔했다. 기존 서비스 테스트가 잡아 복원했다.
  • flaky 테스트 — StreamingResponseBody는 비동기라 MockMvc에서 asyncDispatch가 필요하다. 누락 시 단독 실행에서는 통과하고 함께 돌리면 zip 본문이 비어 실패했다.

실행하지 못한 검증

  • 전체 리그레션 — service 패키지 전체 실행 시 여러 Spring 컨텍스트가 동시에 떠 OutOfMemoryError: Java heap space가 발생한다. 이번 변경과 무관한 환경 문제이며, 확인하려면 힙을 늘려 별도 실행해야 한다.
  • 브라우저 런타임 — 프리뷰가 열리지 않았고(뷰포트 0x0), 관리자 화면 확인에는 백엔드 기동 + LDAP 로그인 + 지원자 데이터가 필요하다.
  • 렌더 시간 실측 — 테스트는 지원서 2건 기준이라 20건 실사용 소요 시간은 확인되지 않았다.

미결 사항

#항목현재 입장
1 일괄 20건 렌더 소요 시간 추정 6~20초. 실측 후 상한(20)과 프론트 timeout(120초) 적정성을 재확인한다
2 실데이터 기준 PDF 레이아웃 더미 데이터로만 확인했다. 실제 지원서(장문 자기소개서, 다수 자격증)로 검증 필요
3 목록 인쇄 버튼 용도 껍데기로 보존 중. 브라우저 인쇄 동선이 필요한지 아니면 제거할지 미정
4 표 경계선 색 화면은 #f0f0f0이나 인쇄 시 선이 사라져 #d9d9d9로 한 단계 진하게 적용. 화면 그대로가 낫다면 되돌린다
5 경력 최종직급(승진일) 표현 화면은 헤더를 colspan="2"로 묶고 값을 두 칸으로 나눈다. PDF는 한 칸에 대리 (2024-01)로 합쳤다
6 페이지 이동 시 선택 초기화 화면에 보이지 않는 항목이 선택된 채 남으면 의도치 않은 PII 반출로 이어져 초기화하도록 했다. 페이지를 넘나들며 누적 선택이 필요하면 되돌릴 수 있다
7 PII export 권한 분리 현재는 기존 admin 권한 사용. AdminExportController.EXPORT_APPLICATION_PII 상수가 분리 의도를 남겨두었으므로 role matrix 세분화 시 함께 적용
8 프론트 라벨 오타 (ENFOLLED) 범위 밖이라 미수정. 화면에서 "재학"이 영문으로 표시된다

다음 단계 권장

  1. 런타임 검증 — 지원자 21명 이상인 공고에서 페이징, 단건/일괄 PDF, 엑셀 필터 적용을 확인한다.
  2. 렌더 시간 실측 — 일괄 20건 소요 시간을 측정해 미결 1번을 닫는다.
  3. 실데이터 PDF 검토 — 레이아웃 조정이 필요하면 템플릿만 수정하면 된다.
  4. 전체 리그레션 — 힙을 늘려 ./gradlew clean test를 별도 실행한다.
