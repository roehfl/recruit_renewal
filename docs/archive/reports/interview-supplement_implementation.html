면접 추가사항 (interview-supplement) - 구현 결과

구현 완료 작성일: 2026-09-26

요약

면접 대기 중인 지원자가 마이페이지에서 미리 등록된 질문에 정해진 시간 안에만 답을 적는 기능을 백엔드·관리자 화면·지원자 화면까지 구현했습니다.

추가사항은 면접단계마다 켜고 끄며, 입력 가능 시간은 지원자별로 둡니다(기본값: 조의 도착시간 ~ +2시간). 관리자는 질문 설정 / 입력 시간 설정 / 답변 조회 탭에서 관리합니다.

입력 허용은 서버 시각으로만 판정하고 종료 뒤 저장은 유예 없이 거부합니다. 지원자 화면의 카운트다운은 기기 시계가 아닌 서버가 준 남은 초로 셉니다.

관계 구조

엔티티 그래프

Stage (면접 유형)
  └── InterviewSupplement (0..1)
       ├── InterviewSupplementQuestion (N)
       │    └── InterviewSupplementAnswer ──► JobApplication
       └── InterviewSupplementWindow ──► JobApplication

대상 지원자 = Stage 의 CONFIRMED Interview
              · CANDIDATE · ASSIGNED · 지원서 WITHDRAWN 아님
기본 시간   = Interview.arrivalDateTime ~ +2시간

설계 결정

  • 지원자별 시간과 답변은 지원서 기준이라 스케줄을 다시 올려 조가 바뀌어도 남습니다.
  • 기본값과 같은 시간을 저장하면 지원자별 행을 지워 "기본값" 상태로 되돌립니다.

시간 판정 정책

핵심 정책 서버 시각만 믿는다

입력 대기→ (시작 ≤ now)→ 입력 가능→ (now = 종료, 유예 없음)→ 입력 마감
  • 서버: 입력 화면 조회와 저장 모두 매번 LocalDateTime.now(clock)으로 다시 판정합니다. 기기 시계를 바꾸거나 모달을 억지로 열어 둬도 마감 뒤 저장은 400입니다.
  • 모달: 서버가 준 remainingSeconds를 받은 순간부터 performance.now()로 셉니다. 저장 응답마다 다시 맞춥니다.
  • 손실 줄이기: 입력 1.5초 뒤 자동 저장, 남은 3초 이하에서는 즉시 저장, 0이 되면 닫고 안내합니다.
  • 목록 버튼: endDateTime − remainingSeconds로 서버 시각을 추정해 30초마다 갱신합니다.

결정 로그

#결정근거
1입력 시간은 지원자별, 기본값 = 조 도착시간 ~ +2시간사용자 요구(지원자별 조정)
2추가사항은 면접단계별로 켜고 끔모든 면접에 있는 기능이 아님(사용자 요구)
3마감 유예 없음사용자 결정(엄격). 대신 자동 저장·마감 직전 즉시 저장
4답변 평문 저장, 지원서 파기 시 함께 파기사용자 결정, 자기소개서 답변과 같은 방식
5새 테이블 운영 DDL 파일 미작성사용자 결정(ddl-auto)
6답변 있는 질문 삭제·끄기 금지작성된 답변 보호
7관리자 화면은 설정 탭 2개 + 조회 탭, 본문 최대 폭 1080px디자인 검토 결과
