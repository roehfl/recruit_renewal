메시지 발송 S1 - 템플릿 구현

구현 완료 미커밋 작성일: 2026-09-19

요약

메일·SMS 메시지 발송 기능의 첫 slice(S1)로, 관리자가 메시지 종류별 템플릿을 등록·수정·삭제하고 종류당 기본 템플릿 1개를 지정하는 기능을 구현했습니다.

본문의 #{변수}는 서버 enum MessageVariable이 종류별 허용 목록의 단일 출처이며, 허용되지 않은 변수는 저장 단계에서 400으로 막습니다. 화면은 /admin/messages/templates입니다.

작업은 6개 묶음으로 나눠 구현했고, 묶음마다 스펙 리뷰와 품질 리뷰를 거쳤습니다. 최종 리뷰에서 Critical·Important 이슈는 없었습니다. 변경은 사용자 요청에 따라 main 작업 트리에 커밋 없이 남아 있습니다.

검증 및 비즈니스 규칙

규칙설명
채널 조합메일은 제목·본문을 함께 채우거나 함께 비움. 메일·SMS 중 하나 이상 필수. 공백만 있는 값은 null
변수 허용없는 키·다른 종류의 변수는 400 "사용할 수 없는 변수: #{…}"
기본 템플릿기본으로 저장(등록·수정)하면 같은 종류의 다른 기본 해제. 종류를 바꾸면 새 종류 기준
글자 수이름 100, 메일 제목 200, 본문 10,000, SMS 2,000(요청 DTO @Size). 화면의 변수 칩·복제도 한도를 넘지 않음
SMS byteS1은 프론트에서 표시용으로만 계산(127 이하 1byte, 그 밖 2byte). 서버 강제는 S2
예외InvalidMessageException 400, MessageTemplateNotFoundException 404

리뷰 반영 (결정 로그)

#결정근거
1MessageVariable.getTypes()가 수정 불가 Set 반환JVM 전역 enum 상태 오염 방지(ApplicationSectionType 선례)
2저장 응답이 늦게 와도 그사이 다른 템플릿을 골랐으면 선택을 바꾸지 않음저장 중 다른 템플릿 클릭 시 폼이 조용히 되돌아가는 문제
3변수 칩·복제가 글자 수 한도를 넘지 않게 막음코드로 넣은 값에는 maxlength가 적용되지 않아 저장 시 400
4삭제 후·첫 진입 시 필터된 목록의 첫 항목 선택, 템플릿 전환 시 변수 삽입 위치 초기화필터에 가려진 템플릿이 편집기에 뜨는 불일치
5수정 응답 전에 flush()@LastModifiedDate가 응답에 반영되도록(S2 "템플릿으로 저장" 대비)
6기본 템플릿 동시 저장 방지는 두지 않음저트래픽 관리자 화면. 필요하면 스키마 변경으로 대응(카드 기록)
7카드의 SMS byte 규칙을 "S1은 프론트 표시용"으로 정정코드가 기준. 서버 byte 판정은 S2에서 추가
