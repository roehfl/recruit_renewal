Phase 09 — 개인정보 파기 / 감사 / 보존 (Privacy Purge · Audit · Retention)

신영증권 채용 Renewal 백엔드 · 설계 리포트 · 설계 확정 구현 대기 · 생성일 2026-06-04 (grill-with-docs) · rev 2026-06-04 (instruction.md 리뷰 #1~#7 반영)

1. Executive Summary

Phase 09 는 두 기둥을 감사 우선(audit-first) 순서로 설계했다. ① 현재 SLF4J 로만 남는 감사 이벤트를 영속 ActivityLog(append-only)로 이관하고 정보 반출·핵심 관리자 변경·파기 lifecycle 을 증적으로 남긴다. ② 보존기간이 경과한 지원자 개인정보를 tombstone 익명화 + 첨부 바이너리 물리삭제 방식으로 파기하고 PurgeBatch/PurgeJobItem 원장과 감사로 남긴다.

진행 가능 여부: 설계·용어(glossary)·ADR(0005/0006/0007)이 확정되어 구현 슬라이스 9a → 9b → 9c → 9d-1 → 9d-2 → 9e 착수 가능. 비가역 파기는 검증된 감사 기반 위에서만 실행.
불변 원칙: "DB 는 PURGED 인데 디스크에 파일 바이트 잔존" 상태는 절대 불허. PURGED = 관계형 PII 제거 AND 첨부 바이너리 소멸 확인까지 완료된 최종 상태.
2026-06-04 리뷰 반영(instruction.md): ① PII 필드 인벤토리를 9d 선행 산출물로 격상 → docs/codex/implementation/phase-09-pii-field-inventory.md(전 application 엔티티 필드 분류). ② terminal query 구체화(실제 enum 검증). ③ metadataJson → typed AuditMetadata. ④ PhysicalFileStatus.DELETED → SOFT_DELETED 분리. ⑤ requestMatcher HTTP method 분기. ⑥ 9b read API 가드. ⑦ ADR accepted 게이트(ADR-0005 = accepted-with-implementation-gate).

3. 아키텍처 / 도메인

신규 엔티티 · 관계

RetentionPolicy (global default + per-JobPosting override) JobPosting.hiringEndedAt ──▶ retentionAnchorAt ──▶ eligibility(Clock) RetentionHold ──▶ (onboarded/입사확정/HR 이관만 자동 제외) PurgeBatch (DRY_RUN | EXECUTE) └─ 1:N PurgeJobItem (append-only, application 별 결과) └─ targetType / status / reasonCode / erased counts JobApplication ─(tombstone)─ purgeBatchId · purgeResult · purgedAt ├─ sections/answers : 원문 PII 익명화 └─ ApplicationAttachment : physicalFileStatus saga + filenameHash ActivityLog (append-only) ── purge 는 batch 단위 coarse index 만 ├─ applicationId / applicantRefHash(HMAC) 로 연결 └─ 지원자 파기 job 이 수정·삭제·마스킹하지 않음

데이터 소유 / 보존 규칙

  • ActivityLog = 영속 감사 증적 source of truth. SLF4J recruit.audit.* 는 보조. 지원자 원문 PII 미저장(단 actorId/ip/ua/applicationId/applicantRefHash 포함 → "완전 PII-free" 아님).
  • PurgeBatch/PurgeJobItem = 파기 상세 원장(무엇을 파기했나). ActivityLog 는 coarse index(누가 했나).
  • tombstone = 비식별 골격(ids/posting/position/stage·result code/날짜차원/purge 메타). 원문 PII 없음.
  • ref-count: Applicant 공통 PII 는 그 Applicant 의 모든 JobApplication 파기 시에만 익명화.
핵심 클래스(계획): ActivityLogService(recordInCurrentTx/recordRequiresNew), RetentionEligibilityService(Clock), PurgeExecutionService(item-level tx), AttachmentPurgeSagaService, StorageHealthScanService(확장), AdminAuditController, AdminRetentionController.

4. 파기 saga (stateful saga + reconciliation)

첨부 바이너리 삭제는 DB 트랜잭션과 원자화 불가 → 트랜잭션이 아니라 saga. 관계형 PII 제거만으로 PURGED 보고하지 않는다.

① DB tx : PII·originalFilename 제거, attachment/item = BINARY_DELETE_PENDING, JobApplication.purgeResult = PURGE_PENDING → commit ② 파일삭제: deleteIfExists(멱등) + 존재 재확인 (이미 없음 = MISSING_AS_SUCCESS) ③ DB tx : 소멸 확인 → PURGED / purgedAt 확정 실패 → BINARY_DELETE_FAILED / PARTIAL_FAILED (재시도 대상) reconciliation sweep : PENDING/FAILED 재처리 storage-health-scan : "DB PURGED 인데 파일 존재" = 치명적 불일치 탐지
"파일 소멸 + DB pending" = 프라이버시상 안전(나중에 PURGED 승격).
"DB PURGED + 파일 잔존" = 불허(역방향).
트랜잭션 입도application 1건 = item tx(all-or-nothing). batch = 비원자 집계(COMPLETED/PARTIAL_FAILED). batch FAILED = 시작/criteria 생성 실패만. ALREADY_PURGED = idempotent skip.
dry-run vs execute별도 batch. execute 에 sourceDryRunBatchId(bulk 필수). execute 는 dry-run 을 믿지 않고 실행시 eligibility 재검증.

6. 검증 / 정책 규칙

감사 트랜잭션 (ADR-0006)

  • 커밋 변경 성공 → in-tx(원자적, afterCommit 금지)
  • 실패/거부/충돌/스킵 → REQUIRES_NEW
  • 정보 반출 → 별도 tx + fail-close
  • append-only(정정=correction event), @Version 불필요

파기 eligibility

  • anchor 종료 + retentionPeriod 경과 + not purged + not hold + terminal
  • terminal = WITHDRAWN ∨ (finalStage 1개 ∧ status∈{RESULT_ANNOUNCED,CLOSED} ∧ StageResult.resultStatus≠PENDING ∧ decidedAt≠null)
  • finalStage 부재/2개↑ = INVALID_STAGE_CONFIGURATION SKIP
  • anchor 암묵 fallback 금지 → ANCHOR_NOT_FIXED
  • SKIP reasonCode: RETENTION_NOT_DUE / RETENTION_HOLD / ALREADY_PURGED / ANCHOR_NOT_FIXED / APPLICATION_NOT_TERMINAL

actionResult enum

  • SUCCESS / FAILURE / DENIED / SKIPPED / CONFLICT
  • CONFLICT(낙관적 락/버전) = FAILURE 와 분리
  • 상태성(STARTED/REQUESTED/COMPLETED) = actionType 으로

RetentionHold (보존 예외)

  • 자동 제외 = onboarded/입사확정/HR 이관 완료만
  • 중간 전형 PASSED 는 제외 기준 아님
  • 불합격·전형포기·미응시·입사포기·미확정 종료 = retention 경과 시 파기 대상
권한 분리(ADR-0007): purge execute / RetentionPolicy·Hold write / 감사 원문(ip·ua)·purge 원장 원문 = ROLE_PRIVACY_ADMIN. dry-run/scan · retention 조회 · 마스킹 audit 목록 · policy read = ROLE_RECRUIT_ADMIN. DeptRoleMapping 파생(하드코딩 금지).
