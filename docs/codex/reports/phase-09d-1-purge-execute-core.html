1. Executive Summary

비가역 파기의 실행 core. ① POST /purge-batches/execute(PRIVACY_ADMIN · confirm=true · bulk=sourceDryRunBatchId의 ELIGIBLE만/단건 XOR), ② 실행 시 eligibility 재검증(dry-run 불신뢰 — drift 는 SKIPPED 기록), ③ 관계형 PII tombstone — PII 인벤토리 §3~§7 분류표를 1:1 구현(PLACEHOLDER/NULLIFY/HASH_ONLY/KEEP 불가침), ④ Applicant ref-count 익명화(ciHash = "PURGED:"+UUID sentinel), ⑤ item=REQUIRES_NEW all-or-nothing / batch=비원자 집계(PARTIAL_FAILED) / PURGE_EXECUTE coarse 감사. 바이너리 소멸 미확인(STORED·soft-DELETED) 시 PURGED 승격 금지 — 물리삭제/최종 승격은 09d-2 saga.

2. 완료 범위

A Execute API + 안전장치

  • PRIVACY_ADMIN narrow matcher(broad 보다 먼저)
  • confirm=true 명시 필수 · bulk/단건 XOR
  • bulk 후보 = 근거 dry-run(DRY_RUN 검증)의 ELIGIBLE item 만
  • criteria 실패는 batch 생성 전 400/404

B Tombstone(인벤토리 계약)

  • 전용 ApplicationPiiPurgeRepository — bulk JPQL 12종(createdBy updatable=false 대응)
  • 학력·경력 정확 날짜 전부 null(안 A) · 자격번호 HMAC HASH_ONLY
  • 평가 comment per-candidate 만 — Interview 공유 텍스트 불가침
  • 섹션 엔티티 비로딩 — stale flush 없음

C 원장 전이 + 승격 가드

  • item REQUIRES_NEW all-or-nothing · 실패 item 증적 잔존
  • batch COMPLETED/PARTIAL_FAILED/FAILED + 집계(purged/pending/skipped/failed)
  • STORED·soft-DELETED 잔존 시 PURGE_PENDING(purgedAt 미세팅) — "DB PURGED+파일 잔존" 불허
  • ALREADY_PURGED 멱등 skip

D ref-count + 감사

  • 모든 지원서 파기 대상일 때만 Applicant 익명화(8필드, §2)
  • ciHash sentinel — CI 연결 단절(재가입 허용=파기 우선)
  • PURGE_EXECUTE coarse 감사 + PurgeExecuteMetadata
