Recruit Backend - Phase 05d

Publish/Layout Guard Integration
CompletedGenerated/Updated: 2026-05-27

Executive Summary

Phase 05d integrated layout validation into the job posting publish workflow. A posting can no longer be published with a stale or invalid layout configuration.

The publish guard validates stored layouts against the current effective section set. When no stored layout exists, a deterministic fallback is generated and validated (always passes for migration compatibility).

Two existing service classes were modified and 3 new tests were added to JobPostingServiceTest.

Can move forward All targeted tests passed including layout regression tests.

Publish Flow Integration

Step Component Action
1 JobPostingService.publish() Status check (not CLOSED, not already PUBLISHED)

3 JobPostingService.publish() Job positions validation
4 NEW ApplicationFormLayoutService Layout validation (stored or fallback) against effective sections

Validation Decision Flow

Condition Action Result
No ApplicationFormConfig Throw exception Publish blocked
Stored layout exists and valid Validate stored layout Publish allowed
Stored layout exists but stale Validate stored layout Publish blocked
No stored layout Generate fallback, validate Publish allowed (fallback always valid)
