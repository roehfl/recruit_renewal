Recruit Backend Codex Report

Phase 03j - JobPosting Domain Display & Position Metadata Expansion Design

Design Completed

Generated on 2026-05-22. Documentation-only design phase for expanding job posting display metadata and job position classification metadata.

Executive Summary

이번 설계는 기존 최소 CRUD 수준의 JobPosting, JobPosition을 지원자 공고 목록/상세와 관리자 공고 관리 화면에 맞게 확장하는 방향을 정리했다.

핵심 결정은 운영 상태와 공개 노출 여부를 분리하고, 접수 기간과 화면 노출 기간을 분리하는 것이다.

ReceptionStatus는 DB에 저장하지 않고 응답에서 파생하며, 공개 목록은 접수중, 접수예정, 접수마감 순으로 정렬한다.

숨김 공고는 공개 조회와 신규 지원서 생성을 차단하지만, 이미 작성 중인 지원서 수정/제출/철회는 기존 접수기간 정책을 유지한다.

이번 Phase에서는 Java 소스, 테스트, DB schema, runtime API를 변경하지 않았다.

Current Problem

DomainCurrent StateProblem
JobPosting title, contentHtml, 접수기간, status, 게시/마감 시각 중심 짧은 설명, 공고 구분, 공개 노출 기간, 상단 고정, 수동 정렬, 접수 상태 표시를 안정적으로 처리하기 어렵다.
JobPosition positionName, headcount, sortOrder 중심 지원구분, 직군, 세부 직무, 근무지, 고용형태를 분리할 수 없어 검색/필터/태그/통계 확장에 불리하다.
Public Query PUBLISHED만 조회하고 createdAt desc에 가깝게 정렬 운영 상태와 공개 노출이 결합되어 있고, 공개 화면용 deterministic 정렬 기준이 부족하다.

Display And Query Policy

Public Filter

  • status = PUBLISHED
  • visible = true
  • displayStartDateTime이 없거나 현재 이전
  • displayEndDateTime이 없거나 현재 이후

Public Sort

  • pinned desc
  • receptionStatusPriority asc
  • displayOrder asc
  • receptionEndDateTime asc
  • publishedAt desc
  • id desc

Reception Status

  • UPCOMING: 접수 시작 전
  • ACCEPTING: 접수 기간 안
  • CLOSED: 접수 종료 후
  • DB 저장 없이 응답에서 계산

접수마감 공고도 display 기간 안이면 노출될 수 있으므로 접수 종료일 오름차순보다 receptionStatusPriority를 먼저 적용한다. 구현은 JPQL CASE WHEN 정렬을 우선 검토하고, Service 정렬은 전체 결과를 정렬한 뒤 pagination하는 경우에만 사용한다.

accepting은 기존 호환용 접수기간 기반 boolean이다. status=PUBLISHED와 접수기간 안쪽 여부만 포함하며 visible/display 조건은 포함하지 않는다.

Application Command Policy

CommandPolicyReason
신규 지원서 생성 PUBLISHED, 접수중, visible=true, display 기간 안쪽 조건을 모두 적용 숨김 공고 ID를 직접 호출해 신규 지원서를 생성하는 우회 경로를 차단한다.
기존 지원서 수정/제출/철회 PUBLISHED와 접수기간 안쪽 조건 유지. visible/display 조건은 적용하지 않음 운영자가 목록 노출을 내렸더라도 이미 작성 중인 지원서 흐름은 보존한다.

이번 Phase에서는 creatable, applicationCreatable, publiclyVisible 같은 추가 boolean 응답 필드를 만들지 않는다. 신규 지원서 생성 가능 여부는 response field가 아니라 service guard에서 판단한다.

DB Impact

TableColumnsCompatibility Strategy
job_posting posting_type, summary, display_start_date_time, display_end_date_time, visible, pinned, display_order 기존 데이터는 PUBLIC_RECRUITMENT, visible=true, pinned=false, displayOrder=0로 보정한다. enum은 문자열 저장, boolean은 DB default와 Java default를 함께 둔다.
job_position application_type, job_group, job_title, work_location, employment_type 기존 positionName, headcount, sortOrder는 유지한다. jobGroup, workLocation은 초기 nullable로 두고 임시 문자열을 저장하지 않는다.

Validation Rules

JobPosting

  • title, contentHtml 필수
  • summary 최대 500자 후보
  • summary HTML 태그 포함 시 400으로 거절
  • 접수 시작은 종료보다 이전
  • 노출 시작은 노출 종료보다 이후일 수 없음
  • displayOrder >= 0
  • CLOSED 공고 일반 수정 금지 유지

JobPosition

  • 모집분야 최소 1개
  • positionName 필수
  • jobGroup, workLocation은 초기 nullable
  • headcount >= 1 유지
  • sortOrder >= 0
  • 같은 공고 request 내 sortOrder 중복 금지 권장
  • EmploymentType 재사용
