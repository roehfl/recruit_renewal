1. Executive Summary

지원자 loginId 정책(이메일 = loginId vs 별도 ID)이 미결정인 상태에서, 어느 안이 채택되어도 유효한 계정 기능을 구현했다. ① 현재 코드에 실재하던 loginId 무결성 결함 수정(User 레벨 중복체크 + DB unique 제약 + LDAP JIT race 복구), ② 가입 화면용 이메일 중복체크 API, ③ 지원자 비밀번호/전화번호 변경 API, ④ DB 제약 위반 409 응답 정비. 설계 문서의 리뷰 2차 반영본(LDAP 재인증 제거, 복구 범위 한정)을 그대로 구현했다. audit 파이프라인 비접촉 — Phase 09b 진행에 영향 없다.

2. 완료 범위 (Scope Cards)

Scope A loginId 무결성

  • User.loginId에 unique = true (JOINED 부모 테이블 제약 — H2 테스트로 동작 실증)
  • UserRepository.existsByLoginId 신설 · signUp 중복체크 User 레벨 전환
  • ApplicantRepository.existsByLoginId 제거
  • JIT race 복구: save 충돌 시 재조회 → LDAP 재인증 없이 buildEmployeeAuthentication 토큰 생성
  • 정규화는 trim only(대소문자 semantics 후속 결정)

Scope B check-email API

  • GET /auth/applicants/check-email (permitAll 명시)
  • 컨트롤러 @Validated + @NotBlank @Email @Size(255)
  • signUp과 동일 trim 정규화 후 existsByEmail 판정
  • 응답은 {available}만 — advisory 전용

Scope C/D 계정 변경 API

  • POST /applicant/account/password — currentPassword 확인 + 동일 새 비밀번호 거부 + BCrypt 저장
  • POST /applicant/account/phone-number — currentPassword 재확인 + trim 저장
  • 기존 /api/applicant/** 보호 네임스페이스 하위 — SecurityConfig 변경 불요

Scope E 횡단 보강

  • DataIntegrityViolationException → 409 generic + 원인 warn 로그
  • InvalidApplicantAccountException → 400
  • Applicant.changePassword / changePhoneNumber 의미 메서드

6. 도메인 구조 / JIT race 복구

User(abstract, JOINED 상속) ← Applicant/Employee 구조 불변. users.login_id에 unique 제약이 추가되어 동시 가입·동시 JIT race의 backstop이 된다.

JIT race 복구 흐름: LDAP 인증 성공 → Employee save에서 DataIntegrityViolationException → findUserByLoginId 재조회 → Employee면 이미 인증된 ldapUser로 토큰만 생성(LDAP 인증 총 1회) → 양쪽 요청 모두 로그인 성공. Employee가 아니거나 부재면(deptName unique 등 loginId race 외 제약 위반 / 지원자 가입 선점) 원본 예외를 전파해 인증 실패 처리.

7. Validation / 비즈니스 규칙

#규칙실패 응답
1loginId 중복체크는 users 테이블 전체(임직원 포함)400 "이미 사용 중인 아이디입니다."
2User.loginId DB unique — race backstop, null은 비충돌409 (race 시)
3check-email은 signUp과 동일 trim 정규화 후 판정, available만 응답400 (형식/blank)
4비밀번호 변경: currentPassword 일치 → 8~100자 → 현재와 동일 거부 → BCrypt 저장400
5전화번호 변경: currentPassword 일치 + NotBlank/max 30 + trim 저장400
6DB 제약 위반 409 generic(내부 정보 비노출, 원인 warn 로그) — 전 엔드포인트 적용409 "이미 처리되었거나 중복된 데이터입니다."
7JIT loginId race만 복구(LDAP 인증 1회), 그 외 제약 위반은 예외 전파—
8name/ci는 변경 API로 열지 않음(본인인증 산출물)—
