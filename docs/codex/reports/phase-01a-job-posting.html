Entity 관계 요약

  • JobPosting 1 : N JobPosition
  • JobPosting 1 : 1 ApplicationFormConfig
  • JobPosition.jobPosting은 LAZY N:1 관계다.
  • ApplicationFormConfig.jobPosting은 LAZY 1:1 관계이며 job_posting_id가 unique다.
  • JobPosting 저장/수정 시 모집분야와 지원서 항목 설정은 cascade/orphanRemoval 정책으로 aggregate 내부에서 관리된다.

주요 비즈니스 규칙

  • 공고 제목과 본문은 공백일 수 없다.
  • 접수 종료일시는 접수 시작일시보다 이후여야 한다.
  • 모집분야는 최소 1개 이상 필요하다.
  • 지원서 항목 설정은 생성/수정 요청에 항상 포함되어야 한다.
  • 신규 공고는 항상 DRAFT 상태로 생성된다.
  • 일반 수정 API는 status를 받거나 변경하지 않는다.
  • 일반 수정은 CLOSED 상태에서 차단된다.
  • DRAFT -> PUBLISHED 전환은 가능하다.
  • PUBLISHED -> CLOSED 전환은 가능하다.
  • CLOSED -> PUBLISHED 재전환은 차단된다.
  • publish/close 시각은 주입된 Clock 기준으로 저장한다.
  • 관리자 목록 page는 0 이상, size는 1 이상 100 이하만 허용한다.
  • 관리자 pageable 목록 조회에서는 collection 관계를 fetch하지 않는다.
  • 관리자 상세 조회에만 @EntityGraph로 jobPositions, applicationFormConfig를 함께 조회한다.
  • PUT API는 사용하지 않는다.
