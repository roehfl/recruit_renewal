Recruit Backend Phase Report

Phase 03c-9 - Application Question/Answer Domain Design

지원서 자기소개서/질문답변 도메인을 구현하기 전 설계를 정리했다. 이 보고서는 Markdown 설계 문서를 기반으로 만든 self-contained HTML이며, Java 코드와 DB schema는 변경하지 않는다.

Design Only Recommendation Fixed No Tests Required No Java / No Schema Generated: 2026-05-18 +09:00

Design Decision

  • 추천 구조는 QuestionTemplate + JobPostingQuestion + ApplicationAnswer.
  • QuestionSet은 묶음/version 요구가 생길 때까지 보류한다.
  • 자기소개서는 별도 Entity가 아니라 SELF_INTRODUCTION 카테고리로 본다.

Scope

  • 설계 문서와 HTML report만 생성/갱신한다.
  • 기존 Phase 03c-8 HTML 명령 마스킹 오류를 보정한다.
  • 기존 상세 섹션 API와 submit validator는 변경하지 않는다.

Next Step

  • 다음 구현 추천은 Phase 03c-9-1.
  • QuestionTemplate과 JobPostingQuestion 관리자 질문 구성 API를 먼저 구현한다.
  • 그 뒤 지원자 답변 저장, submit 검증, 관리자 답변 조회를 연결한다.

Self Introduction Policy

자기소개서는 별도 table이나 별도 Entity로 분리하지 않는다. "지원동기", "성장과정", "입사 후 포부" 같은 항목은 QuestionCategory.SELF_INTRODUCTION으로 분류된 공고별 질문으로 처리한다.

  • 공고별 자유 질문과 자기소개서 항목은 동일한 JobPostingQuestion 구조를 사용한다.
  • 지원자는 동일한 ApplicationAnswer 구조로 답변한다.
  • 화면에서 자기소개서 탭이 필요하면 category 필터로 구성한다.

Submit Validator Integration

  • active + required JobPostingQuestion을 공고 기준으로 조회한다.
  • ApplicationAnswer를 지원서 기준으로 조회해 질문 id별 map을 만든다.
  • required 질문 답변이 없거나 answerText가 null/blank이면 실패한다.
  • answerText가 질문의 maxLength 또는 기본 상한을 초과하면 실패한다.
  • 공고 질문이 없으면 submit을 통과한다.
  • 이번 Phase에서는 ApplicationSubmitValidator 구현을 수정하지 않는다.

Admin Detail Extension

Phase 03c-8의 관리자 상세 섹션 lazy 조회 흐름을 유지해 GET /admin/applications/{applicationId}/answers 후보를 둔다.

응답 필드 후보설명
questionId, questionText질문 식별자와 질문 문구. 과거 답변은 snapshot 우선 사용 가능
category, answerType질문 분류와 답변 타입
required, maxLength, sortOrder표시와 검증 정책
answerId, answerText, updatedAt답변 정보. 미답변이면 answer 관련 필드는 null 후보

Privacy / Audit

  • answerText에는 지원자가 민감 개인정보를 직접 입력할 수 있다.
  • 관리자 상세에서는 업무상 원문 노출을 허용하되 관리자 목록에는 포함하지 않는다.
  • 원문 열람 권한, 열람 사유, 감사 로그는 후속 보안 Phase에서 설계한다.
  • PDF/엑셀 출력에 답변 원문을 포함할지는 별도 출력/다운로드 Phase에서 결정한다.

Verification

  • 설계 문서 작업이므로 테스트는 실행하지 않는다.
  • Java 코드, 테스트 코드, Gradle, YAML, DB schema, static 리소스를 변경하지 않는다.
  • HTML report는 inline CSS만 사용하며 외부 CDN, 외부 JS, 외부 CSS를 사용하지 않는다.
  • Phase 03c-8 HTML report의 PowerShell 테스트 명령은 $env:AES_SECRET_KEY='***'; .\gradlew.bat ... 형태로 마스킹한다.
