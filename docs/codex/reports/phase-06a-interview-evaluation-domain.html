Phase 06a - 면접 평가 도메인

구현 완료 작성일: 2026-05-28

요약

Phase 06a는 면접 평가 도메인의 영속성 모델을 구현합니다. 한 면접관이 한 면접에서 한 후보자에 대해 수행한 평가를 InterviewEvaluation 엔티티로 표현합니다.

등급 체계(EvaluationGrade) 결정을 반영했으며, 평가 근거 자료로서 StageResult를 어디서도 참조하지 않습니다.

이번 slice는 엔티티 · enum · 리포지토리 · 대상 테스트만 추가합니다. API/서비스/컨트롤러는 06b 이후에 추가됩니다.

상태 전이

EvaluationStatus 생애주기

(initialize) → DRAFT → (updateContent) → DRAFT → (submit) → SUBMITTED
SUBMITTED → (reopen) → DRAFT

submit는 grade + recommendation이 모두 있어야 하며 submittedAt을 설정한다. reopen은 submittedAt을 초기화한다. updateContent와 submit은 DRAFT에서만, reopen은 SUBMITTED에서만 가능하다.

검증 및 비즈니스 규칙

#규칙
1후보자/면접관 모두 InterviewParticipant로 참조
2candidateParticipant.role = CANDIDATE, interviewerParticipant.role = INTERVIEWER
3두 참가자는 해당 평가의 interview에 속해야 함
4jobApplication/stage는 initialize 시 파생되며 이후 불변
5grade/recommendation은 DRAFT 시 nullable, submit 시 필수
6comment는 선택, 최대 2000자
7DRAFT만 updateContent/submit 가능
8SUBMITTED만 reopen 가능, reopen 시 submittedAt 초기화
9엔티티는 StageResult를 어디서도 참조하지 않음
