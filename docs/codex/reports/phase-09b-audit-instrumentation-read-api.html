1. Executive Summary

09a foundation(영속 ActivityLog + 2경로 기록) 위에 실제 감사 데이터가 쌓이기 시작하는 슬라이스. ① 기존 SLF4J 감사 로거(Export/Pdf/Upload)를 dual-write adapter로 흡수(DB = source of truth, SLF4J 보조), ② 정보 반출 fail-close(감사 commit 전 반출물 미전송 + temp xlsx 누수 방지), ③ 핵심 관리자 변경 in-tx 계측(StageResult 정정·발표·확정, 평가 reopen, 첨부 admin download/delete), ④ sealed typed AuditMetadata(PII-free allowlist 고정), ⑤ admin audit read API(권한별 마스킹/원문 + read 가드).

2. 완료 범위

A typed AuditMetadata(sealed)

  • record 7종 고정: Export/Pdf/Upload/UploadConflict/StageResultChange/EvaluationReopen/AttachmentAdmin
  • 업로드 파일명 원문 금지 — hash+확장자만(SLF4J 포함)
  • EXPORT_STAGE_RESULT_TEMPLATE actionType 추가
  • 계약 테스트로 taxonomy/PII-금지 고정

B dual-write + egress fail-close

  • Export/Pdf 로거: DB 먼저(REQUIRES_NEW, 실패 시 throw) → SLF4J
  • export 컨트롤러 5곳: 감사 실패 시 temp xlsx 삭제 후 전파(누수 방지)
  • Upload: APPLIED=in-tx(commit 트랜잭션 join) · REJECTED_VALIDATION=FAILURE · REJECTED_STALE/낙관락=CONFLICT

C 관리자 변경 in-tx 계측

  • 정정(단건/bulk) STAGE_RESULT_CORRECT — upload 와 이중 기록 방지
  • 발표 STAGE_RESULT_ANNOUNCE · 확정 STAGE_RESULT_CONFIRM
  • reopen EVALUATION_REOPEN · 첨부 삭제 ATTACHMENT_ADMIN_DELETE
  • 첨부 다운로드 ATTACHMENT_ADMIN_DOWNLOAD(fail-close)
  • AuditRequestContextResolver — 시그니처 오염 없이 actor/ip/ua 해석

D Read API + 가드

  • GET /admin/audit/activities(+단건)
  • page≤100 · range≤90일 · default 최근 30일
  • ip/ua = PRIVACY_ADMIN 만 원문, RECRUIT_ADMIN 은 ***
  • narrow matcher 를 broad /api/admin/** 보다 먼저
