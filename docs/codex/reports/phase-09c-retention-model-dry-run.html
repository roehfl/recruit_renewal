1. Executive Summary

보존/파기의 산정 기반 슬라이스. ① RetentionPolicy(전역+override, overlap 금지, scanAt 기준 선택 규칙 + fail-safe POLICY_CONFLICT), ② RetentionHold(manual only, release=마킹), ③ JobPosting.hiringEndedAt 수동 anchor 명령(자동 세팅·암묵 closedAt fallback 금지), ④ RetentionEligibilityService(설계 terminal query 계약 — 판정 순서 고정), ⑤ 무변경 dry-run PurgeBatch/PurgeJobItem(delete 금지 ledger) + PURGE_SCAN coarse 감사. 파기 실행(execute)·tombstone 은 09d-1.

2026-06-05 구현 리뷰 반영(Medium 2 + Low 3): hold 조회를 PRIVACY_ADMIN 전용으로 좁힘(자유 텍스트 reason 노출 차단 — 권장안), retention write/dry-run 4개 서비스에 requireActor (ANONYMOUS 감사 차단), batch 목록 page/size 가드(max 100, PageResponse 전환), 서비스 레벨 null 필드 방어(Bean Validation 우회 경로 대비), active hold 중복 race 는 후속 항목으로 문서화.

2. 완료 범위

모델 Retention 도메인

  • RetentionPolicy — periodDays/baselineType(HIRING_ENDED_AT|CLOSED_AT)/enabled/effective window
  • RetentionHold — manual only · active 중복 금지 · 사유 원문은 도메인만
  • JobPosting.hiringEndedAt + 수동 anchor 명령
  • JobApplication 파기 marker 3컬럼(09c 읽기 전용)

산정 선택 규칙 + Eligibility

  • override > global · scanAt 기준 window · 부재=NOT_FOUND · 2+ 후보=POLICY_CONFLICT(fail-safe)
  • 판정 순서 고정: PURGED→HOLD→POLICY→ANCHOR→NOT_DUE→STAGE_CONFIG→NOT_TERMINAL
  • terminal = WITHDRAWN OR (finalStage 1개·발표/확정·결과 결정)
  • Clock 주입 scanAt — 판정 컴포넌트는 시계 비의존

Dry-run 무변경 preview

  • PurgeBatch(DRY_RUN) + item(ELIGIBLE/SKIPPED+reason) — 도메인 무변경
  • 집계: total/eligible/skipped/policyConflictCount
  • ledger delete 금지(repository 계약)
  • 감사 = batch 단위 PURGE_SCAN coarse index 만(in-tx)

인가 ADR-0007 matcher

  • write(정책 CUD/hold/anchor) = ROLE_PRIVACY_ADMIN
  • GET·dry-run = RECRUIT·PRIVACY
  • HTTP method 분기 narrow matcher 8종 — broad 보다 먼저
