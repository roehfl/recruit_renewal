1. Executive Summary

파기 lifecycle 의 마지막 안전망. ① reconciliation sweep — PURGE_PENDING 잔여 건의 바이너리 삭제를 재처리해 소멸 확인 시 최종 PURGED 승격(execute 재실행은 ALREADY_PURGED skip 이라 유일한 재처리 경로), ② storage-health-scan §6.1 상태별 정책 — "DB PURGED + 파일 잔존" 치명탐지(PURGED_PHYSICAL_FILE_PRESENT) + BINARY_DELETED null path 정상 분류 + BINARY_DELETE_PENDING/FAILED retry 가시화, ③ Low 2 — row 수준 sanitized 실패코드(binaryDeleteFailureCode), ④ 권한/멱등/Clock 회귀 하드닝. reconcile 도 "소멸 확인 후에만 PURGED" 불변식 승계.

2. 완료 범위

A Reconciliation sweep

  • POST /retention/purge-batches/reconcile — PRIVACY_ADMIN narrow matcher
  • PURGE_PENDING → 원 batchId 로 saga ②③ 재구동 → 최종 PURGED 승격
  • 단건 실패 격리 · null batchId 조기 가드(적대 검증 반영)
  • PURGE_RECONCILE coarse 감사 + 멱등(재sweep 무대상)

B health-scan §6.1

  • PURGED 지원서 파일 = 치명(PURGED_PHYSICAL_FILE_PRESENT)
  • BINARY_DELETED + null path = 정상(오탐 금지 — Low 1)
  • BINARY_DELETE_PENDING/FAILED = retry(issue 아님) + 카운트
  • 이슈는 fileKeyHash 만(경로/파일명 PII 미노출)

C Low 2 실패코드

  • binaryDeleteFailureCode(sanitized, row 영속)
  • EMPTY_STORAGE_PATH / STILL_EXISTS / INVALID_STORAGE_PATH / DELETE_FAILED / EXCEPTION
  • 성공(BINARY_DELETED) 시 null 해소 · saga Set→Map 전파

D 하드닝 회귀

  • reconcile 권한(RECRUIT 403/PRIVACY 200)·멱등·actor 부재 거부·FAILURE 감사
  • 치명탐지/Low 1 정상분류 테스트
  • AuditMetadataContract permits 11종(Map.ofEntries 전환)
