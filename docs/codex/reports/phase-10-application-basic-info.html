Executive Summary

지원서 작성 중 입력하는 지원자 기본정보(이름·생년월일·국적·연락처·이메일·보훈·장애·주소)를 지원서별 1:1 섹션 엔티티 ApplicationBasicInfo로 저장·조회한다.

모든 문자열 PII는 AesAttributeConverter로 at-rest 암호화한다. DB NOT NULL 제약은 FK(job_application_id)만이며, 파기(Purge) 시 전 PII 컬럼을 null로 처리한다.

제출 검증(항상 최우선), 완성도 체커(BASIC_INFO 필수 그룹), 관리자 조회 API, PDF 스냅샷 배선(BasicInfo source of truth), 파기 saga 편입까지 전체 수직 슬라이스가 완료됐다.

테스트는 scoped 실행으로 검증 완료. 전체 테스트 스위트는 로컬 환경 타임아웃으로 미실행.

다음 단계로 진행 가능. 증명사진(PHOTO)·CommonCode 시드·Excel export 배선은 후속 슬라이스.

파기 (Purge)

보안 정책: AES 랜덤 IV(비결정적) → 암호화 컬럼에 '__PURGED__' 평문 치환 불가(복호화 시 깨짐). 전 PII 컬럼 null 처리. 파기 후 행 자체는 보존(파기 marker = JobApplication).
처리 방식대상 컬럼
NULLIFY (전부)nameKorean, nameEnglish, email, mobilePhone, emergencyPhone, birthDate, nationalityType, countryCode, veteranStatus, disabilityStatus, disabilityGradeCode, disabilityTypeCode, zipCode, addressBasic, addressDetail, createdBy, updatedBy
유지 (KEEP)id, jobApplication (FK), createdAt, updatedAt
