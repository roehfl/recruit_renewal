Fix — 수동 인증/인가 상태코드 정정 (400 → 401/403)

신영증권 채용 Renewal 백엔드 · cross-cutting 수정 리포트 · 반영 완료 테스트 97/97 · 2026-06-04

1. 요약

일부 API 에서 "Authentication is required" 오류가 400 으로 응답되던 문제를 정정했다. 원인은 서비스 레이어 수동 인증 체크(CurrentEmployeeService/CurrentApplicantService)가 400 매핑 도메인 검증 예외를 재사용했기 때문이다. 미인증은 401, 인증됐지만 타입 불일치는 403 으로 분리했다.

프론트엔드 분기 가능 — 401 수신 시 로그인 라우트 이동(axios interceptor). 백엔드는 redirect 하지 않는다 (분리형 SPA + 세션 구조에서 302 는 XHR/CORS 문제 유발 — 기존 CustomAuthenticationEntryPoint 401 JSON 패턴과 동일 노선).

2. 상태코드 계약

미인증 (userDetails == null) → 401 AuthenticationRequiredException "... authentication is required." 타입 불일치 (employee↔applicant) → 403 AccessForbiddenException "Only ... users can access ..." 도메인 검증 실패 → 400 (기존 유지) Security 필터 레벨 → 401 EntryPoint / 403 DeniedHandler (기존 유지, 변경 없음)

5. 잔여 이슈 / 다음 단계

  • 구조적 한계 근본 원인 SecurityConfig 의 anyRequest().permitAll() 은 유지 — URL 레벨 1차 방어선 부재. permitAll → authenticated + 공개 경로 allowlist 전환은 공개 API 전수 확인이 필요한 별도 슬라이스 (9b 의 audit matcher 추가와 함께 검토 권장, ADR-0007).
  • 프론트 작업 Vue axios interceptor: 401 → 로그인 라우트, 403 → 권한 안내(프론트 저장소).
  • 유지 blank actor·미존재 사용자 체크는 인증/인가가 아니므로 기존 400 계열 예외 유지.
