Phase 03d-4/03d-5: Result Read and Correction Design

신영증권 채용 Renewal 백엔드의 StageResult 다음 단계를 지원자 결과 조회와 발표 후 결과 정정 이력으로 분리한 설계 보고서다. Updated: 2026-05-19

Design Only

Phase Summary

이번 작업은 설계 문서와 HTML 리포트만 작성한다. Java, 테스트, 설정, schema, SecurityConfig는 변경하지 않는다.

Phase 03d-4

Applicant Read

GET /applications/{applicationId}/stage-results 후보를 정의하고 발표 상태 기반 visibility guard를 고정한다.

Phase 03d-5

Correction

발표 후 결과 변경은 별도 correction command와 append-only history로 분리한다.

Executive Summary

  • 지원자 결과 조회는 본인 지원서만 허용하고 DRAFT 지원서는 대상에서 제외한다.
  • READY, IN_PROGRESS 단계는 발표 전 row로도 노출하지 않는다.
  • 지원자 응답은 stageName, stageType, stageOrder, resultStatus, resultAnnouncementDateTime, decidedAt 중심으로 제한한다.
  • score, comment, decidedBy, correction history는 지원자 응답에서 제외한다.
  • 발표 후 정정은 최신 StageResult를 변경하고, 변경 전후 값을 StageResultCorrectionHistory에 남긴다.

Domain and Ownership Rules

  • StageResult는 최신 결과 record로 유지한다.
  • StageResultCorrectionHistory는 append-only 이력 record다.
  • 지원자 API는 StageResultCorrectionHistory를 조회하지 않는다.
  • 지원자 API는 Stage.status를 1차 visibility guard로 사용한다.
  • 관리자 application timeline은 기존처럼 발표 visibility guard를 적용하지 않는다.

  • 예약 발표가 필요하면 resultAnnouncementDateTime 기반 guard를 후속 확장
