Phase 03j-1 - Job Posting Domain Expansion Status Completed
Generated: 2026-05-22

Executive Summary

Phase 03j-1 extended the internal admin job posting domain without adding new endpoint paths.

JobPosting now stores posting type, summary, display policy, visibility, pinning, and display order. JobPosition now stores application type, job group, job title, work location, and employment type.

New application creation now requires a published, accepting, visible posting inside its display period. Existing application update, submit, and withdraw commands keep their previous status and reception-period guard.

Review fixes added direct Service validation for DTO constraints and replaced admin list lazy collection counting with a grouped position-count query.

The targeted phase regression suite passed, so the phase can move to public exposure design and implementation.

  • JobPosting owns one ApplicationFormConfig row.

  • ApplicationFormConfig updates in place to avoid one-to-one unique key conflicts.

Validation / Policy

Validation Rules

  • title and contentHtml are required.
  • Reception end must be after reception start.
  • summary must not contain HTML tags and must be 500 characters or less.
  • Display end must be equal to or after display start when both are present.
  • displayOrder must be 0 or greater when provided.
  • Position name, headcount, sort order, and 100-character metadata limits are validated in Service as well as Controller.
  • Position sortOrder values must be unique.

Default Rules

  • postingType: PUBLIC_RECRUITMENT
  • visible: true
  • pinned: false
  • displayOrder: 0
  • applicationType: NEW_GRADUATE_OR_EXPERIENCED
  • employmentType: FULL_TIME

Application Guard

  • New create: published, accepting, visible, and inside display period.
  • Draft update: published and accepting.
  • Submit: published and accepting.
  • Withdraw: published and accepting.
