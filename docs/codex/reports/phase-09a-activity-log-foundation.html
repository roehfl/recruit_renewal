1. 요약

Phase 09(개인정보 파기/감사/보존)의 첫 슬라이스. 영속 감사 증적의 기반만 구현했다 — 영속 ActivityLog(append-only), 감사 enum 5종, append-only repository, 기록 서비스 2경로 (recordInCurrentTx/recordRequiresNew), correlationId 필터, applicantRefHash(HMAC+pepper).

업무 이벤트 계측·API·보존/파기 도메인은 이 슬라이스에 없다 — 기존 로거 흡수/관리자 변경 감사/read API 는 9b, 보존/파기는 9c~9e.
관찰: 컨텍스트에 Quartz 스케줄러 존재 → 9c/9e retention 스케줄(설계상 disabled-by-default)에 @Scheduled 대신 Quartz 활용 가능(별도 검토).

3. 기록 트랜잭션 2경로 (ADR-0006)

recordInCurrentTx (REQUIRED) 커밋된 변경 성공 증적 → 비즈니스 tx 에 join(원자적, 함께 rollback) recordRequiresNew (REQUIRES_NEW) 실패/거부/충돌/스킵 + 정보 반출(fail-close) → 비즈니스 rollback 무관 보존 emission = 명시적 호출(AOP blanket 아님) · 외부(09b)에서 호출(self-invocation 회피)
occurredAt주입 Clock 기준(테스트 fixed Clock)
applicantRefHashHMAC_SHA256(AUDIT_HMAC_SECRET, "APPLICANT:"+applicantId) — 입력 applicantId 만, plain SHA-256(ciHash)과 분리
metadataJsontyped AuditMetadata 만, 전용 ObjectMapper 로 서비스 내부 직렬화(앱 web Jackson 분리)
correlationIdX-Request-Id 또는 UUID(CorrelationIdFilter) → MDC → 기록

5. 도메인/스키마

ActivityLog = 독립 테이블 activity_log, FK 없음. jobPostingId/applicationId 는 denormalized search key(파기 후 join 회피), applicantRefHash 는 가명 연결자. append-only(setter/update/@Version 없음). 지원자 원문 PII 미저장(단 actorId/ip/ua/applicationId/applicantRefHash 포함). enum 은 @Enumerated(STRING), index 7종(09a-RF 에서 (action_result, occurred_at) 추가). dev/test 는 ddl-auto 자동 생성, 운영(MariaDB)은 수동 DDL(docs/codex/ops/phase-09a-activity-log-ddl.sql — 09a-RF).

6. 검증 규칙

  • append-only — update/delete API·setter·@Version 없음. 정정은 correction event(9b+).
  • 트랜잭션: 커밋변경=in-tx, 실패/거부/충돌/스킵·반출=REQUIRES_NEW.
  • applicantRefHash 입력 applicantId 만(원문 PII 금지), HMAC≠plain SHA-256.
  • metadataJson typed record 만, 직렬화 서비스 내부.
  • AUDIT_HMAC_SECRET 누락=기본 기동실패(fail-safe, profile 무관). fallback 은 audit.allow-fallback-secret=true 명시 시에만(09a-RF).
  • request-derived 문자열은 저장 직전 sanitize+truncate — 외부 입력 길이가 audit insert 실패로 전이되지 않음(09a-RF).
  • 필수필드(occurredAt/actorType/actionType/actionResult/targetType) 누락 → InvalidActivityLogException.
