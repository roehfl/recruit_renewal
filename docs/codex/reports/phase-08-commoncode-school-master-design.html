Phase 08 · CommonCode & School Master 설계

신영증권 채용 Renewal 백엔드 · documentation-only 설계(grill-with-docs) · 생성일 2026-06-02

요약

관리자가 런타임에 관리하는 코드성 lookup(CommonCode)과 학교 자동완성/통계 기반(School) master 를 추가형(비파괴)으로 도입한다. CommonCode 는 프론트 드롭다운 소스로만 쓰고(백엔드 검증 미결합), 기존 enum 은 하나도 전환하지 않는다(카탈로그만). School 은 ApplicationEducation 에 optional schoolId 로만 연결(강한 FK 없음)해 학교별 통계 기반을 만든다. 본 단계는 설계 문서만 — 구현은 08a~08c 후속.

범위

In Scope

  • CommonCode 엔티티 + admin CRUD + public read
  • School 엔티티 + 검색/자동완성 + admin CRUD + xlsx import(upsert)
  • ApplicationEducation optional schoolId
  • enum 전환 후보 카탈로그(STAY/CANDIDATE)

Out of scope

  • 기존 enum → CommonCode 전환(0건)
  • CommonCode ↔ 백엔드 필드 validation 결합
  • SCHOOL/CERTIFICATE funnel dimension(07c 보류)
  • 외부 학교 API, 강한 FK, free-text 소급 매칭

slice 계획

  • 08a CommonCode
  • 08b School 검색/CRUD
  • 08c xlsx import + schoolId 링크

API (구현 슬라이스 후보)

MethodPath접근Purpose
GET/api/codes?groupCode=publicactive 코드 목록(sortOrder 순)
GET/POST/PUT/api/admin/codesadmin코드 관리(비활성 포함, code 불변)
GET/api/schools?q=&schoolType=public이름 검색 top-N(active)
GET/POST/PUT/api/admin/schoolsadmin학교 관리
POST/api/admin/schools/importadminxlsx 일괄 upsert(07d parser 재사용)

public read 는 SecurityConfig anyRequest().permitAll() 로, admin 은 /api/admin/** 로 자동 커버 — 보안 설정 변경 불필요.

enum 전환 후보 카탈로그 (전환 0)

STAY enum 유지

  • 상태머신: *Status 전부
  • 분기/정책: StageResultStatus, EducationLevel, MilitarySubjectType, Question*/Section* 등
  • 척도: EvaluationGrade/Recommendation
  • 내부/API: Funnel/Upload/Menu/Notice

CANDIDATE 표시 전용

  • MilitaryBranch/Rank/ServiceType
  • EmploymentType, JobPositionApplicationType
  • DayNightType, CampusType
  • (borderline 재검증: GraduationStatus, StageType, AttachmentType)

CANDIDATE 도 Phase 08 에선 전환하지 않는다 — "관리자 런타임 추가" 요구가 생긴 group 만 별도 전환.
