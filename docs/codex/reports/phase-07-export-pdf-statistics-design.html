Executive Summary

Phase 07은 운영자가 admin 데이터를 다루는 reporting 계층을 설계한다. 네 기둥은 Excel download(읽기), Statistics funnel(읽기), Excel upload(쓰기, StageResult 한정), Application PDF(읽기)다. 리스크가 낮은 read-only를 먼저, 위험한 쓰기와 무거운 PDF 의존성을 뒤로 배치한다.

  • 13개 핵심 결정 + instruction.md 10항목 리뷰 반영(총 20 Decision Log). 4-critic adversarial 리뷰로 보정.
  • 새 entity/table/migration 없음 — export/statistics/PDF는 read-only, upload는 기존 StageResultService 재사용.
  • InterviewEvaluation upload은 Phase 06 경계(배정 면접관만 평가 작성)상 영구 제외.
  • ci/ciHash/password는 어떤 export/PDF/statistics에도 노출하지 않음.
Phase 진행 가능: 설계 확정. 다음은 07a(Excel export 인프라 + applications download) 구현.

Validation & Policy

전형 funnel 단계 분포 (합 = |P|)

P = { app | app.submittedAt != null }   (현재 status 무관, 코호트 고정 → 재현 가능)

stage k 분포 (raw 7 버킷, 합 = |P|):
  PASSED | FAILED | ABSENT | HOLD | PENDING | WITHDRAWN | NO_RESULT
  PENDING   = StageResult row 있음, 결정 전
  NO_RESULT = row 자체 없음(미초기화/미도달) — 응답 전용 synthetic, enum/upload 입력값 아님
  distribution.withdrawn(=stage result status) ≠ population.withdrawnCount(=application status)

순차 통과 집합:  S0 = P ,  Sk = S(k-1) ∩ {stage k == PASSED}
비율(funnelPassedCount 기준): 누적 = |Sk| / |P| ,  전환 = |Sk| / |S(k-1)|

Export & Row Cap

  • 대응 list와 동일 필터, page/size 무시(전체 행 export).
  • 생성 전 count 선검증 → count > maxRows(기본 50,000)이면 workbook 미생성, 400 EXPORT_ROW_LIMIT_EXCEEDED.
  • 전 export · PDF · upload commit에 SLF4J 구조적 audit.
PII 정책. ci/ciHash/password는 어떤 export/PDF/statistics에도 절대 미포함. name/phoneNumber/email은 applications export + PDF에서 평문 노출(운영 연락), 노출 시 audit. Statistics는 집계값만(audit 없음). PDF는 가장 집중된 PII surface라 생성 시 audit(actor/applicationId/jobPostingId/jobPositionId/timestamp) 필수.
보안 보강(instruction.md 리뷰). Excel formula injection 방어(export string cell + 위험 prefix escaping, upload formula cell 거부) · PDF 템플릿 th:utext 금지 + 외부 resource load 금지 + 줄바꿈 CSS pre-wrap · audit schema 표준화(공통/ export/ PDF/ upload commit 필드, PII 직접 기록 금지) · 권한 정책 상수 EXPORT_APPLICATION_PII 여지(향후 role matrix 분리용).
