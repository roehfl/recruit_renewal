Recruit Backend - Phase 03j-2

Public Job Posting Exposure, Filter, Sort, and Response Contract

Completed Generated: 2026-05-22

Executive Summary

Phase 03j-2 updates the existing public job posting APIs so applicant-facing list and detail reads use the new public exposure policy.

Only published, visible, displayable postings are public. Reception period is not an exposure filter, so closed reception postings may still appear with receptionStatus=CLOSED and accepting=false.

The public list now uses database ordering and loads positions for the current page in one batch query. Review follow-up tightened sort tie-break tests and removed the obsolete status-only public repository method.

Architecture / Domain

JobPostingRepository.findPublicList applies public filters and sorting before pagination. JobPostingPublicService then loads all positions for the page posting ids through JobPositionRepository.findByJobPostingIdInOrderByJobPostingIdAscSortOrderAsc.

The earlier unused findAllByStatusOrderByCreatedAtDesc public status-only query method was removed because the public service now uses the exposure-aware query.

Detail reads use an entity graph for jobPositions and applicationFormConfig while applying the same public exposure conditions.

Excluded Internal Fields

Public responses do not expose status, visible, displayStartDateTime, displayEndDateTime, displayOrder, createdAt, updatedAt, or closedAt. Public list also excludes contentHtml and applicationFormConfig.
