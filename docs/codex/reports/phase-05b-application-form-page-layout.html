Application Form Page Layout Backend Slice
CompletedGenerated/Updated: 2026-05-26

Executive Summary

Phase 05b implemented the applicant-owned form-page bootstrap API for already-created applications.

The API returns posting, selected position, application status, reception/action flags, form config, and enabled layout sections.

The slice is read-only and preserves existing application creation, draft update, submit, withdraw, section-save, and dashboard behavior.

Can move forward Targeted service and controller tests passed.

Validation / Policy

Access

  • Current applicant id comes from CurrentApplicantService.
  • Other applicant applications return hidden 404.
  • Anonymous requests return JSON 401 through existing security handlers.
  • Employee/admin requests return JSON 403 through existing security policy.

Action Flags

  • accepting: PUBLISHED and current time inside reception period.
  • editable: DRAFT and accepting=true.
  • No submit or withdraw flags are added in this slice.

Sections

  • BASIC_INFO is always enabled and required.
  • ApplicationFormConfig.useXxx controls enabled config sections.
  • requireXxx controls required config sections.
  • Active questions expose QUESTION_ANSWER.
  • Attachment requirement rows expose ATTACHMENT.

Field Exposure

Protected The new response does not expose the following forbidden fields:

applicantId, stageResultId, score, comment, decidedBy, correctedBy, storagePath, storedFileName, correction history, CI/encryption internals, or other applicants' personal data.
