Phase 03d-3 Admin Application StageResult Timeline Lazy API

Generated: 2026-05-19 · Status Completed

관리자 지원서 상세 화면에서 전형 단계별 결과 이력을 lazy 방식으로 조회하는 read-only API를 추가했다.

Executive Summary

CompletedLazy section API
GET /admin/applications/{applicationId}/stage-results
CompletedStage-based rows
지원서 공고의 모든 Stage를 기준으로 row를 반환한다.
CompletedResult merge
StageResult가 있으면 결과 필드를 병합하고 없으면 null로 둔다.
DeferredApplicant read
지원자 결과 조회 API와 발표 노출 정책은 구현하지 않았다.

  • 기존 AdminApplicationSectionController에 GET endpoint를 추가했다.
  • 기존 AdminApplicationSectionService에 getStageResults를 추가했다.

  • DRAFT, SUBMITTED, WITHDRAWN 지원서 상태를 모두 조회 허용했다.
  • decidedBy는 응답에 포함하지 않는다.

Domain Structure

RelationshipPolicy
JobApplication N : 1 JobPosting지원서의 공고를 기준으로 Stage 목록을 찾는다.
Stage N : 1 JobPostingStage가 timeline row의 기준이다.
StageResult N : 1 Stage결과가 있으면 stage id로 merge한다.
StageResult N : 1 JobApplication요청 applicationId에 속한 결과만 조회한다.

Stage 또는 JobApplication에 StageResult 컬렉션은 추가하지 않았다.

Validation Rules

  • applicationId가 없으면 기존 관리자 섹션 API와 동일하게 not found 응답을 반환한다.
  • 관리자 조회이므로 지원자 소유자 검증은 수행하지 않는다.
  • 공고 상태, 접수기간, 결과 발표 여부와 무관하게 관리자에게 조회를 허용한다.
  • StageResult가 없는 Stage도 row로 반환하고 result field는 null이다.
  • 다른 공고의 StageResult는 merge하지 않는다.
  • comment는 관리자 메모 가능성이 있어 applicant-facing 응답 재사용을 금지한다.
