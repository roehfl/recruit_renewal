요약

운영자가 upload-template으로 받은 xlsx로 StageResult를 bulk 변경한다. stateless preview/commit, all-or-nothing, 3중 교차검증, 낙관적 동시성(stageResultUpdatedAt 토큰)을 갖추고 commit은 기존 StageResultService.bulkUpdateResults에 위임해 기존 불변식(Stage IN_PROGRESS guard, PENDING 금지, comment ≤ 2000, actor 필수, 정정 이력/audit)을 그대로 상속한다. 새 entity/table/migration 없음. 테스트 BUILD SUCCESSFUL — 다음 슬라이스(07e PDF)로 진행 가능.

검증 / 정책

항목규칙
업로드 소스upload-template만. applications/stage results export는 소스 아님.
3중 교차검증stageResultId 존재(해당 stage) + applicationId 일치 + path stageId 소속을 모두 만족해야 유효.
resultStatus허용값 = {PASSED, FAILED, ABSENT, HOLD, WITHDRAWN}. blank/PENDING/미허용 → 행 오류.
빈칸 정책score blank → null clear, comment blank → null clear. 변경 없는 행은 commit 제외(stale check도 변경 행에만).
낙관적 동시성2계층: (1) upload commit은 변경 행 PESSIMISTIC_WRITE + 토큰 재검증 → upload-vs-upload row-level STALE(409). (2) StageResult.@Version은 모든 write 경로 간 backstop → 충돌 시 ObjectOptimisticLockingFailureException 409(리뷰 #1, 리뷰2).
all-or-nothingERROR/STALE 1건이라도 있으면 0건 적용. ERROR → 400(REJECTED_VALIDATION), STALE → 409(REJECTED_STALE).
파일 방어.xlsx만(.xls/.csv/.xlsm 거부), 크기/행수 한도, 첫 sheet, header signature, formula 셀 거부, 중복 stageResultId 거부, 셀 string 판독, 토큰 셀 STRING/blank 외 타입 거부(리뷰 #4).
round-trip 충실성template은 formula-escape를 끈 비변형 string cell로 작성 → 특수문자 시작 comment 미수정 재업로드가 오판/오염되지 않음(리뷰 #2).
guard 선검증commit 선두에서 actor + Stage IN_PROGRESS guard를 변경 행 여부와 무관하게 강제(리뷰 #3).
상속 불변식Stage IN_PROGRESS guard, PENDING 금지, comment ≤ 2000, actor 필수, 정정 이력/audit(bulkUpdateResults 경유).

리뷰 반영 (instruction.md · 4 findings)

등급지적반영
High토큰 in-memory 비교만으론 동시 commit lost update 미차단변경 행을 PESSIMISTIC_WRITE로 잠그고 DB 최신값 refresh 후 토큰 재비교(2안, migration 불필요). id 오름차순 잠금으로 deadlock 회피.
리뷰2PESSIMISTIC은 upload-vs-upload만 보호. 기존 비-locking 수동 경로와의 lost update는 미차단(@Version 부재)StageResult.@Version 추가 → 모든 write 경로 flush 버전 검사, 충돌 시 ObjectOptimisticLockingFailureException 409 매핑. PESSIMISTIC+토큰은 row-level UX로 유지. 기존 113 테스트 비파괴 확인.
Hightemplate이 writer의 formula-escape로 comment를 변형 → round-trip 오판/오염template은 escapeFormulaPrefix=false(비변형 string cell)로 작성. 토큰 포맷은 service 단일 소스로 통일.
Medium변경 0건이면 Stage/actor guard 우회commit 선두에서 validateBulkUpdatable(stageId, actor)로 변경 여부 무관 선검증.
Low토큰 셀 타입 검증이 NUMERIC만STRING/blank 외 모든 타입을 row error로 강화.
