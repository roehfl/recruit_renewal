Phase 04d - Interviewer Interview Read

Completed Generated: 2026-05-26

Executive Summary

Phase 04d adds interviewer-owned, read-only interview schedule APIs.

The APIs expose only schedules where the current employee is assigned as an INTERVIEWER participant, and only when the schedule is CONFIRMED or CANCELLED.

DRAFT schedules, other employees' assignments, admin memo, other interviewer lists, and StageResult internals are hidden.

The phase can move to Phase 04e stabilization or the next roadmap phase.

Architecture and Domain

Entity Structure

  • Interview belongs to JobPosting and Stage.
  • InterviewParticipant belongs to Interview.
  • Interviewer reads only interviewer participant rows.
  • Interviewer rows point to Employee.
  • Detail candidate rows point to JobApplication.

Data Ownership

  • Employee id is resolved from session principal login id.
  • No API accepts employee id or user id.
  • Repository queries apply ownership and visibility together.
  • Non-owned or non-visible details return not found.

API List

MethodPathPurposeRequestResponse
GET /interviewer/interviews?status=&from=&to= All visible schedules assigned to current employee as interviewer. Optional query params only. ApiResponse<List<InterviewerInterviewSummaryResponse>>
GET /interviewer/interviews/{interviewId} One visible schedule detail with assigned candidates. Interview id. ApiResponse<InterviewerInterviewDetailResponse>

Validation Rules

Visibility

  • Visible: CONFIRMED, CANCELLED.
  • Hidden: DRAFT.
  • Interviewer rows only.
  • participantStatus = ASSIGNED only.
  • Current employee assignment only.

Candidate List

  • Loaded after interviewer ownership is verified.
  • Assigned candidate participants only.
  • Cancelled candidate participants are excluded.
  • Other interviewer rows are not exposed.

Forbidden Response Fields

  • Admin memo and cancel/internal memo.
  • Other interviewer employee id/name/department.
  • Interviewer participant list.
  • StageResult status, history, and announcement fields.
