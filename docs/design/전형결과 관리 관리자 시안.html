확정된 방향

  • 1
    공고 선택 → 단계 탭
    단계는 공고별 동적 목록(Stage). 고정 서브메뉴 대신 공고에 설정된 단계가 그대로 탭이 된다.
  • 2
    화면에서 직접 판정
    행 체크 → 합격/불합격/보류/결시 일괄 적용, 또는 행별 셀렉트. "변경사항 저장" 한 번으로 bulk API 호출. 엑셀은 보조 경로로 유지하되 업로드 전 미리보기(diff) 필수.
  • 3
    단계 상태가 UI를 결정
    READY: 초기화·시작 / IN_PROGRESS: 편집·발표 / 발표·마감 후: 잠금 + 사유 필수 정정. 백엔드 가드와 1:1.
  • 4
    단계 설정은 이 화면의 드로어
    공고 상세·지원서 설정 현황판에는 "전형 단계 설정 →" 링크만 둔다(절충).

시안 A · 상단 스텝퍼

장점

  • 전형 흐름(서류 → 1차 → 최종)이 진행 상태와 함께 한 줄로 읽힘
  • 그리드 가로폭 온전히 사용 (열 13개도 여유)
  • 지원서 설정·공고 화면과 같은 세로 흐름, 학습 비용 낮음

단점

  • 단계 6개 이상이면 스텝 폭이 좁아짐 (현실적으론 3~4개)
  • 단계별 카운트를 스텝 안에 다 못 넣음 (선택 단계만 아래 카운트 카드)

시안 B · 좌측 단계 레일

장점

  • 단계 수·이름 길이에 강함
  • 레일에 선택 단계 카운트를 항상 노출, 본문은 그리드만

단점

  • 사이드바 + 레일 = 좌측 내비 2겹, 그리드 폭 200px 손해
  • 진행 순서가 세로라 "흐름" 느낌 약함
