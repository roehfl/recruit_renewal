# 관리자 대시보드 시안 요청서

/ admin 진입 시 표시되는 초기 화면(`AdminHomeView`). 진행 중인 채용 현황을 시각적으로 파악하는 것이 목적이다.
현재는 "좌측 메뉴에서 관리할 항목을 선택하세요" 플레이스홀더만 있다.

---

## 0. 확정 사항 (2026-08-11, 1차 시안 리뷰 후)

- **시안 1b(퍼널 중심) 채택.** 단계 퍼널이 화면의 주어다.
- **화면 스코프는 공고 하나.** 상단에서 공고(채용 회차)를 하나 고르면 화면의 **모든** 위젯이 그 공고 데이터만 보여준다. 여러 공고를 한 화면에 나열하는 위젯은 두지 않는다. 1차 시안의 "공고별 전형 진행 단계"가 이 규칙을 어겨 제거한다.
- **A(KPI)는 범위에서 제외.** 얇은 띠 형태로도 넣지 않는다.
- 확정 범위: **B + C + D + E + F**.

---

## 1. 프레임 제약 (기존 화면에 붙어야 함)

시안은 이미 구현된 `AdminLayout` 안의 **우측 콘텐츠 영역**을 채우는 형태여야 한다.

| 요소 | 값 |
|---|---|
| 좌측 사이드바 | 240px 고정, `linear-gradient(180deg, #0f4726 0%, #0a3a1e 100%)` |
| 콘텐츠 배경 | `#f5f7fa` |
| 콘텐츠 패딩 | `22px 24px` |
| 카드 | 배경 `#fff` · 테두리 `1px #e5e7eb` · radius `12px` · shadow `0 4px 14px rgba(0,0,0,.04)` |
| 폰트 | Pretendard |
| 브랜드 그린 | `#0f4726` |

**브랜드 그린은 UI 크롬 전용이다** — 버튼, 활성 상태, 강조 배지. 차트 시리즈 색으로 쓰지 않는다(아래 5장 팔레트 사용).
관리자 화면은 **라이트 모드 전용**이므로 다크 모드 시안은 불필요하다.

## 2. 위젯 목록

형태(form)는 데이터가 하는 일에 따라 지정했다. **임의로 바꾸지 말 것** — 특히 파이/도넛과 이중 축은 금지다(4장).

### A. 상단 KPI — ~~스탯 타일~~ **제외 (0장 참조)**

KPI 타일 행은 넣지 않는다. 퍼널 카드 하단의 요약 수치(전체 통과율 · 최대 이탈 구간 · 평균 체류)가 그 역할을 대신한다.

### B. 전형 퍼널 — 핵심 시각화

| 위젯 | 형태 | 색 |
|---|---|---|
| 단계 퍼널 (지원→서류→1차→2차→최종) | **가로 막대**, 단계 간 전환율 직접 라벨 | 순서형 램프 |
| 단계별 결과 구성 (합격/탈락/불참/취소/보류) | **가로 스택 막대**, 세그먼트 사이 2px 서피스 갭 | 카테고리 5슬롯 |
| 분야별 퍼널 비교 | **스몰 멀티플** (분야 3개 초과 시 facet) | 슬롯 1 단색 |
| 학교별 / 자격별 topN + 기타 | **가로 막대** (이름이 길어 가로) | 슬롯 1 단색 |

사다리꼴 퍼널 도형은 쓰지 않는다 — 도형 면적이 값에 비례하지 않아 오독을 만든다. 길이로 인코딩하는 가로 막대가 정직하다.

### C. 지원 추이

| 위젯 | 형태 | 색 |
|---|---|---|
| 일자별 지원 접수 추이 | **라인** (단일 시리즈 → 범례 불필요, 제목이 시리즈명). 마감일에 수직 기준선 | 슬롯 1 |
| 공고별 지원자 수 비교 | 가로 막대 | 슬롯 1 단색 |
| 분야별 지원자 분포 | 가로 막대 | 슬롯 1 단색 |
| 작성 중 → 제출 전환율 | **미터** (단일 비율 대 한계) | 슬롯 1 |

### D. 진행 상태 · 일정 — 대부분 차트가 아니다

- 공고별 전형 진행 단계 — **스테퍼 컴포넌트**
- 공고 D-day 타임라인 — 간트형 가로 바
- 결과 발표 예정 — 캘린더 또는 목록
- 오늘/이번 주 면접 일정 — 목록 (확정 `CONFIRMED` vs 미확정 `DRAFT` 구분)

### E. 처리 대기 — 차트 아님, 숫자 + 목록 + 액션 링크

대시보드를 실제로 쓰게 만드는 부분이다. 각 항목은 클릭하면 해당 목록 화면으로 이동한다.

- 면접 평가 미제출 (면접관별)
- 결과 미확정 (대기/보류)
- 미확정 면접 일정
- 발표일이 지났는데 미발표인 단계

상태 표시는 **아이콘 + 라벨과 함께** — 색만으로 의미를 전달하지 않는다.

### F. 지원자 구성

| 위젯 | 형태 | 색 |
|---|---|---|
| 학력 분포 | 가로 막대 (순서 유지) | **순서형 램프** |
| 전공/계열 topN | 가로 막대 | 슬롯 1 단색 |
| 어학 · 자격 보유율 | 가로 막대 또는 미터 | 슬롯 1 |
| 경력 vs 신입 | **가로 스택 막대 1줄** | 카테고리 2슬롯 |
| 연령대 분포 | 가로 막대 | **순서형 램프** |
| 성별 분포 | 가로 스택 막대 1줄 | 카테고리 2슬롯 |
| 보훈 · 장애 | 집계 수치만 |  |

F는 **집계 전용**이다. 개인 식별로 드릴다운하는 동선은 시안에 넣지 않는다.

## 3. 데이터 제약 — 시안에 반영할 것

1. **경쟁률(배수)은 넣지 않는다.** `JobPosition`에 모집인원 필드가 없어 계산이 불가능하다. 필요하면 백엔드 필드 추가가 선행되어야 한다.
2. **집계 API는 퍼널 하나뿐이다.** `GET /admin/job-postings/{id}/statistics/funnel`(공고 단위, dimension = POSITION/SCHOOL/CERTIFICATE)만 존재하고, A·C·D·E·F는 전부 신규 엔드포인트가 필요하다. 시안 단계에서는 무방하나 구현 규모 산정 시 감안한다.
3. **퍼널은 공고 단위다.** 전사 통합 퍼널을 그리려면 별도 집계가 필요하다.
4. 시스템 상태(오류 로그·파기 현황)는 **범위에서 제외**했다. `ROLE_ADMIN`은 해당 API에 403이라 보는 사람마다 화면이 달라진다.

## 4. 시각화 규칙 — 위반 시 잘못된 시안

**형태**
- 이중 축(y축 2개) 금지. 스케일이 다른 두 지표는 차트를 나누거나 공통 기준으로 지수화한다.
- 파이 / 도넛 금지. 부분-전체는 스택 막대를 쓴다.
- 한 칸짜리 막대 차트, 2조각 파이 금지 → 스탯 타일.
- 의미를 가진 색 분류가 7개를 넘으면 표를 쓴다.

**색**
- 카테고리 색은 **고정 순서**로 배정하고 순환하지 않는다. 9번째 색을 만들지 말고 '기타'로 접거나 facet한다.
- 명목 카테고리(공고명, 분야명)에 값 램프를 쓰지 않는다 — 막대 길이를 색으로 이중 인코딩하는 것이다. 단일 색을 쓴다.
- 순서형(퍼널 단계, 학력, 연령대)에만 순서형 램프를 쓴다.
- 상태색(정상/경고/심각/위험)은 예약이다. "시리즈 4"로 재사용하지 않는다.
- 필터로 시리즈가 빠져도 남은 시리즈의 색은 그대로다. 색은 순위가 아니라 대상을 따른다.
- 텍스트는 텍스트 토큰을 쓴다. 값·라벨·범례에 시리즈 색을 칠하지 않는다.

**마크 · 크롬**
- 얇은 마크, 헤어라인 그리드/축. 두꺼운 채도 높은 블록 금지.
- 그리드와 축은 **실선** 헤어라인. 점선 금지.
- 스택 세그먼트와 인접 막대 사이는 **2px 서피스 갭**. 테두리를 둘러 구분하지 않는다.
- **스택 막대 비율은 `flex-basis`가 아니라 `flex-grow`로 준다.** `flex: 0 0 69.5%`처럼 퍼센트를 basis에 박으면 2px 갭이 그 위에 더해져 합이 100%를 넘고 막대가 카드 폭을 뚫는다(`flex-shrink:0`이라 줄지도 않는다). `flex: 69.5 1 0` 형태로 쓰면 갭이 먼저 빠지고 남은 공간을 비율대로 나눠 항상 맞는다. 1차 시안의 "단계별 결과 구성"이 이 문제로 3~5px씩 넘쳤다.
- 아주 작은 세그먼트(1~2%)는 `min-width: 3px`로 최소 폭을 보장한다. 이 크기에는 라벨을 넣지 않고 표 보기로 읽게 한다.
- 모든 데이터 포인트에 숫자를 붙이지 않는다. 끝점·극값·핵심 시리즈만 선택적으로 직접 라벨.
- 시리즈가 2개 이상이면 범례가 항상 있고, 4개 이하는 직접 라벨도 단다. 단일 시리즈는 범례 없이 제목이 이름을 맡는다.
- 막대 안 라벨은 패딩까지 들어갈 때만 넣는다. 안 들어가면 막대 밖이나 툴팁으로 뺀다.
- 카드 높이에 **x축 라벨 밴드를 포함**시킨다. 축이 잘려 카드 안에 세로 스크롤이 생기면 안 된다.

**상호작용 · 접근성**
- 필터는 차트 카드 안이 아니라 **전체 위 한 줄**에 둔다. 모든 차트가 같은 구간으로 다시 그려진다.
- 라인/영역은 크로스헤어+툴팁, 막대/점/셀은 마크별 툴팁을 기본 탑재한다.
- 툴팁이 값을 읽는 **유일한** 수단이면 안 된다. 직접 라벨이나 표 보기로도 읽혀야 한다.
- 모든 차트에 표 보기 트윈을 둔다.

## 5. 검증된 팔레트

아래 값은 실제 서피스(`#ffffff`)에 대해 검증기를 돌려 통과한 것이다. **눈대중으로 바꾸지 말 것** — 바꾸려면 재검증이 필요하다.

### 카테고리 (고정 순서, 6슬롯)

| 슬롯 | 색상 | hex |
|---|---|---|
| 1 | blue | `#2a78d6` |
| 2 | orange | `#eb6834` |
| 3 | aqua | `#1baf7a` |
| 4 | yellow | `#eda100` |
| 5 | magenta | `#e87ba4` |
| 6 | green | `#008300` |

검증 결과: 명도 밴드 · 채도 하한 · CVD 분리(최악 인접 ΔE 9.1) · 정상시야 하한(19.6) 모두 통과.

**단, 대비 경고 3건** — `#1baf7a`(2.82:1), `#eda100`(2.17:1), `#e87ba4`(2.69:1)는 흰 배경에서 3:1 미만이다.
이 세 색을 쓰는 차트는 **직접 라벨 또는 표 보기를 반드시 함께 제공**해야 한다. 선택 사항이 아니다.

### 순서형 램프 (퍼널 단계, 학력, 연령대 — 5단계)

`#86b6ef` → `#5598e7` → `#2a78d6` → `#1c5cab` → `#104281`

검증 결과: 명도 단조 증가 · 인접 명도차 · 밝은 끝 대비(2.11:1) · 단일 색상(색상 폭 3°) 모두 통과.

### 크롬 · 잉크

| 역할 | hex |
|---|---|
| 카드 서피스 | `#ffffff` |
| 페이지 배경 | `#f5f7fa` |
| 기본 텍스트 | `#1f2937` |
| 보조 텍스트 | `#6b7280` |
| 축·라벨 (뮤트) | `#9ca3af` |
| 그리드 헤어라인 | `#e5e7eb` |
| 상태 정상 / 경고 / 위험 | `#0ca30c` / `#fab219` / `#d03b3b` |

브랜드 그린으로 시작하는 차트 팔레트를 원하면 순서를 다시 짜고 재검증해야 한다(재검증 없이 바꾸면 CVD 게이트가 깨진다).

## 6. 요청 사항

위 내용으로 **대시보드 시안 3종**을 만든다. 세 시안은 레이아웃 전략이 서로 달라야 한다(예: KPI 우선 / 퍼널 중심 / 처리 대기 중심).

- 프레임(1장)과 팔레트(5장)는 세 시안 공통으로 고정한다.
- A~F를 한 화면에 다 넣을 필요는 없다. 시안마다 무엇을 위로 올릴지가 차이점이다.
- 스크롤을 전제해도 되지만, **첫 화면(스크롤 없이 보이는 영역)에 무엇이 오는지**를 시안의 주장으로 삼는다.
